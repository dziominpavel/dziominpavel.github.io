# Changelog

Формат: Keep a Changelog, уровни — семантическое версионирование.
Правила ведения: `docs/versioning.md` (источник — корень владельца).

Витрина — статический трек: версия заморожена, теги и GitHub Releases не
ставятся, поэтому версионных секций здесь не будет.

## [Unreleased]

**Добавлено**

- Витрина получила фирменный логотип: круглая иконка на главной и в шапке всех страниц.
- Страница «О проекте»: блок «Обо мне» с фото автора, «Связаться» с кнопками Telegram, Instagram и LinkedIn.
- Подключён счётчик посещений: статистика просмотров доступна в панели GoatCounter.
- Единая лента каталога по дате: карточки идут от самой свежей даты к старой.
- Заметки GitHub-Release берутся из changelog — ранее опубликованные пустые тела залиты.
- На странице приложения появился блок «Что нового» — краткий список изменений последнего релиза со ссылкой на все релизы.

**Исправлено**

- Порядок выезда карточек при переключении фильтра исправлен — строго по порядку сетки.

**Изменено**

- Главная: полоса статистики в hero убрана, фильтр стал единственным местом со счётчиками.
- Витрина пересобирается сразу после релиза или пуша, а не только по расписанию.
- Честная дата web-карточек: дата последнего коммита данных, а не сборки витрины.
- Секции «Откуда данные» и «Почему всё так» убраны со страницы «О проекте».
- Заметки релиза стали пользовательскими по форме — уровень опознаётся и по меткам.

### Добавлено

- Счётчик посещений GoatCounter (`dziominpavel.goatcounter.com`): витрина считает
  просмотры, статистика доступна в панели GoatCounter.
- Логотип: круглая иконка стоит на главной рядом с заголовком и в шапке всех
  страниц вместо буквы «М».
- Единая лента: карточки главной и вывод `--json` идут от свежей даты к старой —
  скачиваемые по дате релиза, web по дате обновления данных; порядок
  `registry.yaml` задаёт только состав каталога.
- Заметки GitHub-Release берутся из changelog: release-скрипт вырезает секцию
  свежей версии (блок до первой строки `###`, у секций без категорий — всю
  секцию) и публикует её телом релиза, тегу — тем же текстом, в UTF-8 без BOM.
  Подготовка релиза отказывается работать, если в секции нет пользовательского
  саммари выше категорий.
- Секция «Что нового» на страницах приложений
  (`show-whats-new-on-app-pages`): `release_card()` берёт `body` из того же
  ответа `releases/latest` (без новых запросов), `notes_body_html()` рендерит
  метки → `<h3>`, буллеты → `<ul>`, прочие строки → `<p>` с полным
  экранированием; пустое тело → секции нет. Тесты: 16 в `test_generate.py`
  (метки/проза/пустое тело/экранирование/позиция на странице), плюс ассерт
  `notes` в `test_release_card_json`; `validate_site.py` — ALL OK.

### Изменено

- Пересборка по событию: release-скрипт шлёт витрине `repository_dispatch` после
  публикации GitHub Release, workflow web-источников — после пуша, тронувшего
  `web/**`/`data/**`; cron (`*/30` и слот `17,47`) остался подстраховкой.
- Фильтр главной: счётчики «Все 9», Android 5, Windows 2, Web 2 — итог считает все
  карточки каталога, включая две веб-версии; волна (0/45/90/… мс) перезапускается
  для всех видимых карточек, поэтому волна от загрузки или прошлого клика не идёт
  параллельно с новой.
- Дата web-карточки: дата последнего коммита папки `web/` источника вместо даты
  сборки витрины.
- Заметки релиза: уровень опознаётся по жирным меткам; формат блока зафиксирован
  в `docs/versioning.md` и правилах AGENTS, доставка — рассылкой на все проекты.
