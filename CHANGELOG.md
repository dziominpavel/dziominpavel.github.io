# Changelog

Формат: Keep a Changelog, уровни — семантическое версионирование.
Правила ведения: `docs/versioning.md` (источник — корень владельца).

Витрина — статический трек: версия заморожена, теги и GitHub Releases не
ставятся, поэтому версионных секций здесь не будет.

## [Unreleased]

- Подключён счётчик посещений GoatCounter (`dziominpavel.goatcounter.com`):
  витрина считает просмотры, статистика доступна в панели GoatCounter.
- Витрина пересобирается по событию, а не только по расписанию: после
  публикации GitHub Release release-скрипт шлёт витрине оповещение
  (`repository_dispatch`), а workflow web-источников — после пуша,
  тронувшего `web/**`/`data/**`. Сборка запускается сразу после релиза
  или пуша; cron (`*/30` и второй слот `17,47`) остался подстраховкой
  и подхватывает пропущенные события.
- Исправлен порядок появления карточек при переключении фильтра главной:
  волна (0/45/90/… мс) перезапускается для всех видимых карточек, поэтому
  волна от загрузки или прошлого клика больше не идёт параллельно с новой,
  и карточки выезжают строго по порядку сетки — как при первом открытии.
- Единая лента каталога по дате: карточки на главной (и вывод `--json`)
  идут вперемешку от самой свежей даты к старой — скачиваемые по дате
  релиза, web по дате обновления данных. Порядок `registry.yaml` задаёт
  только состав каталога.
- Честная дата web без данных: карточка показывает дату последнего коммита
  папки `web/` источника, а не дату сборки витрины.
- Заметки GitHub-Release берутся из changelog: release-скрипт вырезает секцию
  свежей версии (блок до первой строки `###`, у секций без категорий — всю
  секцию) и публикует её телом релиза, тегу — тем же текстом, в UTF-8 без BOM.
  Подготовка релиза отказывается работать, если в секции нет пользовательского
  саммари выше категорий. Тела залиты и в ранее опубликованные релизы всех
  проектов, где они были пустыми.

  (`registry.yaml`, шаблоны, статика).
- Генератор витрины: сборка из реестра и GitHub API, валидация контракта
  репозиториев, авто-детект платформ, страницы приложений.
- Статический релиз-скрипт `release.ps1` v1.0.0 как эталон для проектов.
- Дизайн-токены, переключатель темы (dark/light), фильтр главной, workflow
  автосборки (cron каждые 30 мин + push + dispatch) и валидатор статики.

  из 7 проектов.
- Переименование `InstagrammTracker` → `InstagramTracker` (слаг
  `instagram-tracker`).
- Подготовка ассетов для контракта стора: упаковка zip YandexMusicDownloader,
  PyInstaller-exe InstagramTracker, генератор иконок 512×512.
