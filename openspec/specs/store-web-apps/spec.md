# store-web-apps Specification

## Purpose

Публикация веб-приложений на статической витрине «Мои приложения»: контракт записей в реестре, сборка и хостинг страниц `/apps/<slug>/`, карточки на главной странице, а также поведение размещённых веб-приложений (анализер InstagramTracker, лидерборд Benchmark).

## Requirements

### Requirement: Реестр веб-приложений
`registry.yaml` MUST содержать опциональную секцию `web:` — записи веб-приложений. Ключ записи MUST соответствовать паттерну `[a-z0-9-]` и служить слагом страницы веб-приложения (`/apps/<key>/`). Запись MUST указывать источник статики (репозиторий-источник) и метаданные карточки (название, описание; иконка опциональна). Запись секции `web:` MUST NOT требовать GitHub Release, файла `version` и скриншотов. Добавление веб-приложения в стор MUST требовать только добавления одной записи в секцию `web:` без правок кода стора.

#### Scenario: Добавление третьего веб-приложения
- **WHEN** владелец добавляет новую запись в секцию `web:`
- **THEN** после ближайшей сборки появляются страница `/apps/<slug>/` и карточка на главной, код стора не изменялся

#### Scenario: Некорректный ключ веб-записи
- **WHEN** ключ записи в секции `web:` не соответствует `[a-z0-9-]`
- **THEN** запись отклоняется с предупреждением в логе; остальные записи витрины обрабатываются

### Requirement: Публикация статики веб-приложений
Сборка витрины MUST копировать статику каждой валидной записи `web:` в `_site/apps/<slug>/`, чтобы страница открывалась по прямому URL и полностью работала без серверной части. Страница веб-приложения MUST содержать навигацию обратно в каталог. Язык страницы — только русский. Страница MUST работать без внешних CDN и сторонних хостингов (все ресурсы — с-origin витрины). Sitemap MUST включать страницы веб-приложений.

#### Scenario: Прямая ссылка на страницу
- **WHEN** посетитель открывает `/apps/<slug>/` по прямой ссылке
- **THEN** страница отдаётся, содержит ссылку обратно в каталог и включена в sitemap

#### Scenario: Источник недоступен или битый
- **WHEN** статику получить не удалось (в источнике нет `index.html`, ошибка получения репозитория)
- **THEN** сборка продолжается с предупреждением в логе, страница и карточка этого веб-приложения пропускаются, остальная витрина публикуется; сборка MUST NOT падать

### Requirement: Web-карточки на главной странице
Главная страница MUST показывать карточки веб-приложений в общей ленте вперемешку с карточками скачиваемых приложений по убыванию даты (без отдельной секции и отдельного заголовка): иконка (при отсутствии — буквенная заглушка), название, описание, дата обновления данных и primary-действие «Открыть в браузере» со ссылкой на `/apps/<slug>/`. Дата web-карточки с объявленным `data:` MUST браться из поля `updated` этого файла данных; дата web-карточки без `data:` MUST браться из даты последнего коммита, тронувшего папку `web/` источника, и MUST NOT браться из даты сборки витрины, кроме fallback при недоступности коммит-даты. Макет web-карточки MUST быть консистентен с карточкой скачиваемого приложения. Карточка веб-приложения MUST NOT требовать версию, размер релиза и счётчик скачиваний.

#### Scenario: Два веб-приложения на витрине
- **WHEN** в секции `web:` две записи с разными датами обновления
- **THEN** в общей ленте каждая web-карточка стоит на позиции своей даты среди скачиваемых, каждая ведёт на свою страницу `/apps/<slug>/`

#### Scenario: Иконка веб-приложения отсутствует
- **WHEN** у записи нет файла иконки
- **THEN** карточка показывает буквенный плейсхолдер; сборка MUST NOT падать

#### Scenario: Дата web без данных — из коммита
- **WHEN** у web-записи нет поля `data:` и последний коммит папки `web/` источника датирован 28.09.2026
- **THEN** карточка показывает «Обновлено 28.09.2026», а не дату сборки витрины

#### Scenario: Коммит-дата недоступна
- **WHEN** дату коммита `web/` получить не удалось (ошибка API, пустой ответ)
- **THEN** сборка продолжается с предупреждением в логе, карточка использует дату HEAD клона, а при его отсутствии — дату сборки; остальная витрина публикуется, сборка MUST NOT падать

### Requirement: Сверка `updated` с последним коммитом файла данных
Сборка витрины MUST сверять календарную дату UTC поля `updated` объявленного файла данных web-записи (`data:`) с датой последнего коммита, тронувшего этот файл. Расхождение дат MUST печататься в лог сборки как предупреждение, содержащее слаг web-приложения, значение `updated` и дату коммита. Предупреждение MUST NOT менять дату web-карточки, содержимое собранной статики или код завершения сборки: источником даты карточки остаётся `updated`. Если дату коммита получить не удалось, сверка MUST пропускаться без предупреждения, а сборка и дата карточки MUST при этом не меняться. Сверка MUST выполняться только для web-записей с объявленным полем `data:`; web-запись без `data:` сверка MUST NOT требовать.

#### Scenario: `updated` отстаёт от последнего коммита данных
- **WHEN** web-запись объявляет `data: data/index.json`, поле `updated` равно `2026-10-06`, а последний коммит, тронувший этот файл, датирован `2026-10-07`
- **THEN** сборка печатает предупреждение со слагом и обеими датами, дата карточки остаётся `06.10.2026`, сборка завершается успешно и статика не меняется

#### Scenario: Даты совпадают
- **WHEN** календарная дата UTC поля `updated` равна календарной дате последнего коммита файла данных
- **THEN** предупреждение не печатается, дата карточки берётся из `updated` как обычно

#### Scenario: Коммит-дата недоступна
- **WHEN** дату последнего коммита файла данных получить не удалось (ошибка API, пустой ответ)
- **THEN** сверка пропускается без предупреждения, дата карточки берётся из `updated`, сборка завершается успешно

#### Scenario: Запись без файла данных
- **WHEN** у web-записи не объявлено поле `data:`
- **THEN** сверка не выполняется, дата карточки берётся из даты последнего коммита папки `web/` источника

### Requirement: InstagramTracker Web — анализер экспорта с инструкцией
Страница `/apps/instagram-tracker/` MUST содержать пошаговую инструкцию: куда зайти в Instagram, какие данные выгрузить (формат JSON) и куда загрузить результат. Страница MUST принимать данные экспорта через drag&drop или выбор файла: ZIP-архив, папку либо отдельные JSON-файлы. Разбор экспорта и построение дашборда MUST выполняться целиком в браузере посетителя: содержимое экспорта MUST NOT передаваться ни в один сетевой запрос (допустимы только загрузка статики страницы и счётчик посещений витрины). Результат — дашборд: счётчики подписчиков/подписок и секции аналитики выгрузки; если локально сохранён предыдущий снимок — дополнительно динамика (новые/потерянные). Ошибка разбора MUST показываться понятным сообщением без разрушения страницы.

#### Scenario: Пошаговая инструкция
- **WHEN** посетитель открывает страницу анализера
- **THEN** он видит шаги: куда зайти, что выгрузить, куда загрузить данные

#### Scenario: Загрузка экспорта
- **WHEN** посетитель перетаскивает ZIP-архив экспорта (или папку/JSON-файлы) на страницу
- **THEN** дашборд с аналитикой строится локально, без перезагрузки страницы и без отправки данных на сервер

#### Scenario: Файл не из экспорта Instagram
- **WHEN** посетитель загружает файл не той структуры
- **THEN** страница показывает понятное сообщение об ошибке и остаётся работоспособной

### Requirement: Benchmark Web — статические результаты только на чтение
Страница `/apps/benchmark/` MUST отображать результаты прогонов из `data/index.json` репозитория Benchmark: таблицу ELO-рейтинга моделей (место, название, рейтинг, статистика игр), динамику рейтингов, сводку и ленту последних прогонов, а также дату обновления данных. Страница MUST работать только на чтение: формы ввода, редактирование моделей и управление прогонами на ней отсутствуют. Данные обновляются только при сборке витрины.

#### Scenario: Открытие страницы рейтинга
- **WHEN** посетитель открывает `/apps/benchmark/`
- **THEN** он видит ELO-таблицу моделей, сводку прогонов и дату обновления; форм и элементов управления данными на странице нет

#### Scenario: Обновились данные прогонов
- **WHEN** при сборке витрины `data/index.json` в репозитории Benchmark обновился
- **THEN** после ближайшего деплоя страница показывает обновлённые цифры без каких-либо действий посетителя

### Requirement: Оповещение витрины об обновлении web-статики
Репозиторий-источник веб-приложения, чья статика публикуется на витрине, MUST оповещать витрину (`repository_dispatch`) при пуше, тронувшем статику веб-приложения (`web/**`) либо файл данных (`data/**`), чтобы сборка витрины запускалась без ожидания расписания. Межрепозиторное оповещение MUST выполнять workflow самого репозитория-источника и MUST использовать секрет-токен, предоставляемый владельцем. При отсутствии секрета, его недействительности или ошибке отправки оповещение MUST пропускаться с предупреждением в логе, а пуш и публикация статики MUST NOT блокироваться; изменения в этом случае MUST подхватываться ближайшей сборкой витрины по расписанию. Оповещение MUST отправляться только по пуше, тронувшему статику или файл данных; пуш прочих файлов репозитория оповещение MUST NOT вызывать.

#### Scenario: Пуш статики веб-приложения
- **WHEN** владелец пушит коммит, тронувший `web/**` (для источника с файлом данных — также `data/**`), и репозиторий отправляет оповещение
- **THEN** витрина пересобирается по оповещению, не дожидаясь cron: страница `/apps/<slug>/` отдаёт новую статику, а дата web-карточки обновляется

#### Scenario: Секрет оповещения не настроен
- **WHEN** в репозитории-источнике отсутствует секрет-токен либо он недействителен
- **THEN** оповещение пропускается с предупреждением в логе, пуш проходит успешно, а изменение показывается на витрине после ближайшей сборки по расписанию

#### Scenario: Пуш файлов вне статики
- **WHEN** коммит не трогает ни `web/**`, ни `data/**`
- **THEN** оповещение витрины не отправляется и сборка витрины не запускается

#### Scenario: Релиз приложения, не трогающий статику
- **WHEN** в репозитории опубликован GitHub-Release скачиваемого приложения, а статика веб-приложения не менялась
- **THEN** оповещение о релизе отправляет release-скрипт (capability `app-release-pipeline`), а workflow репозитория-источника статики не срабатывает
