# app-release-pipeline Specification

## Purpose

Единый release-процесс всех приложений: как из исходников получается опубликованный GitHub-Release с ассетами, доступными для скачивания со витрины, при минимальном участии владельца.

## Requirements

### Requirement: Единый release-скрипт в каждом репозитории
Каждый из 7 репозиториев приложений MUST содержать копию единого release-скрипта с одинаковым поведением. Скрипт MUST публиковать релиз из готовых артефактов папки `dist/` (сборка — ответственность билд-скрипта проекта, не release-скрипта). Скрипт MUST печатать свою версию для контроля расхождения копий.

#### Scenario: Релиз через единый скрипт
- **WHEN** владелец запускает release-скрипт после сборки, положившей артефакты в `dist/`
- **THEN** создаётся git tag, публикуется GitHub-Release со всеми артефактами из `dist/`

#### Scenario: Артефактов нет
- **WHEN** release-скрипт запущен, но папка `dist/` пуста
- **THEN** скрипт MUST завершиться с ошибкой и MUST NOT создавать тег или релиз

### Requirement: Версия берётся из файла version
Release-скрипт MUST читать версию из файла `version` проекта (формат `MAJOR.MINOR.PATCH`) и создавать git tag вида `vX.Y.Z` (с префиксом `v`). Версия в имени тега, имени релиза и имени артефакта MUST совпадать. Файл `version` отсутствует ни в одном из 7 проектов не MUST — для проектов, где его нет, он MUST быть добавлен как часть внедрения.

#### Scenario: Текущая версия уже запущена
- **WHEN** тег `vX.Y.Z` из файла `version` уже существует
- **THEN** скрипт MUST завершиться с понятной ошибкой и MUST NOT перезаписывать существующий тег или релиз

#### Scenario: Файл version отсутствует
- **WHEN** release-скрипт запущен в проекте без файла `version`
- **THEN** скрипт MUST завершиться с ошибкой, указывающей на отсутствие файла

### Requirement: Предрелизная проверка иконки
Перед созданием тега release-скрипт MUST проверять наличие обязательной иконки проекта (поле `icon` в `store.yaml` указывает на существующий png). При отсутствии иконки скрипт MUST отказаться от публикации с понятной ошибкой.

#### Scenario: Иконка отсутствует
- **WHEN** поле `icon` указывает на несуществующий файл или не задано
- **THEN** релиз не публикуется, выводится ошибка «нет иконки»

### Requirement: Публикация только через GitHub CLI
Публикация релиза MUST выполняться через GitHub CLI (`gh`) с аутентификацией владельца. Новый релиз по умолчанию MUST быть помечен как обычный (не prerelease), предыдущие релизы проекта MUST NOT изменяться. Исторические версии (архивные артефакты) переносяться в релизы MUST NOT — публикуется только текущая версия.

#### Scenario: gh не установлен или не авторизован
- **WHEN** release-скрипт запущен без доступного/аутентифицированного `gh`
- **THEN** скрипт MUST завершиться с ошибкой, указывающей на установку/авторизацию GitHub CLI, без частичной публикации

### Requirement: Форматы ассетов по платформам
Артефакты в релизе MUST именоваться единообразно: `<Project>-<version>.apk` (Android), `<Project>-<version>-win-x64.zip` (Windows portable), `<Project>-<version>-win-x64.exe` (Windows exe). Windows-сборка из множества файлов MUST упаковываться в один zip на этапе сборки проекта.

#### Scenario: Windows-сборка из многих файлов
- **WHEN** билд-скрипт Windows-проекта собирает exe и зависимости
- **THEN** в `dist/` оказывается один zip-архив, который release-скрипт публикует как есть

### Requirement: Подготовка релиза производит бамп версии
Release-скрипт в фазе подготовки MUST классифицировать содержимое секции `## [Unreleased]` файла `CHANGELOG.md`, определить уровень новой версии по наивысшему накопленному уровню, записать новый номер в файл `version` и свернуть секцию `[Unreleased]` в версионную секцию вида `## [X.Y.Z] — дата (УРОВЕНЬ)`. Подготовка MUST выполняться до сборки ассетов, чтобы в артефакты запеклась новая версия. Подготовка MUST NOT создавать тег, релиз или публикацию. Повышение версии вне релизного процесса MUST NOT выполняться другим механизмом.

#### Scenario: Релиз с накопленными изменениями
- **WHEN** владелец запускает подготовку при непустой секции `[Unreleased]`
- **THEN** файл `version` содержит новый номер, секция `[Unreleased]` заменена версионной секцией, тег и релиз НЕ созданы; последующая сборка запекает новый номер в артефакты

#### Scenario: Секция Unreleased пуста
- **WHEN** подготовка запущена, а секция `[Unreleased]` отсутствует или пуста
- **THEN** скрипт MUST завершиться с понятной ошибкой «нет накопленных изменений», а файл `version` и `CHANGELOG.md` MUST остаться без изменений

### Requirement: Публикация требует проведённой подготовки и чистого дерева
Release-скрипт в фазе публикации MUST отказаться, если секция `[Unreleased]` непуста (подготовка не выполнена). Публикация MUST требовать, чтобы рабочее дерево не содержало незакоммиченных изменений, кроме файлов бампа (`version` и `CHANGELOG.md`), и MUST закоммитить эти файлы до создания тега — иначе тег указывал бы на коммит без описанных в changelog изменений.

#### Scenario: Публикация без подготовки
- **WHEN** публикация запущена, а секция `[Unreleased]` непуста
- **THEN** скрипт MUST завершиться ошибкой с указанием запустить подготовку, тег и релиз MUST NOT быть созданы

#### Scenario: Нечистое рабочее дерево
- **WHEN** публикация запущена при незакоммиченных изменениях в других файлах проекта
- **THEN** скрипт MUST завершиться ошибкой с указанием закоммичить работу, тег MUST NOT быть создан

### Requirement: Отказ при рассинхроне версии и changelog
Перед созданием тега release-скрипт MUST сверять формат файла `version` и верхнюю секцию `CHANGELOG.md` (учитывая только что проведённый бамп). При расхождении скрипт MUST завершиться ошибкой и MUST NOT создавать тег, релиз или публикацию.

#### Scenario: Changelog отстаёт
- **WHEN** верхняя секция changelog не совпадает с файлом `version`
- **THEN** скрипт завершается ошибкой, тег не создаётся, git-состояние проекта не изменено

#### Scenario: Файл version вне формата
- **WHEN** файл `version` содержит не `MAJOR.MINOR.PATCH` (например, суффикс сборки или пустая строка)
- **THEN** скрипт завершается ошибкой с указанием ожидаемого формата

### Requirement: Релиз не публикуется без changelog-секции новой версии
Git-тег релиза MUST указывать на коммит, в котором `CHANGELOG.md` содержит версионную секцию нового номера. Публикация релиза, чей коммит не содержит соответствующей секции, MUST считаться ошибкой и MUST NOT выполняться.

#### Scenario: Тег на коммите без секции
- **WHEN** попытка создать тег выполнена, а в `CHANGELOG.md` нет секции с номером новой версии
- **THEN** скрипт завершается ошибкой и не публикует релиз
