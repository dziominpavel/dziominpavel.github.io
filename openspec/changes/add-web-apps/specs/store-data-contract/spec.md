## MODIFIED Requirements

### Requirement: Реестр проектов в репозитории стора
Репозиторий стора MUST содержать файл `registry.yaml` со списком репозиториев приложений. Реестр состоит из основной секции (скачиваемые приложения) и опциональной секции `web:` (веб-приложения, контракт описывается в capability `store-web-apps`). Ключ записи в обеих секциях MUST соответствовать паттерну `[a-z0-9-]`; ключ основной секции служит слагом страницы приложения (`/<key>/`), ключ секции `web:` — слагом страницы веб-приложения (`/apps/<key>/`). Добавление нового приложения в стор MUST требовать только добавления одной записи в `registry.yaml` (при условии выполнения контракта в самом репозитории).

#### Scenario: Добавление восьмого проекта
- **WHEN** владелец добавляет запись в основную секцию `registry.yaml`, а в репозитории проекта выполнен контракт
- **THEN** после ближайшей синхронизации проект появляется на витрине без правок кода стора

#### Scenario: Некорректный ключ реестра
- **WHEN** ключ записи в `registry.yaml` не соответствует `[a-z0-9-]`
- **THEN** запись отклоняется валидацией с предупреждением; остальные записи обрабатываются

#### Scenario: Секция web не влияет на скачиваемые приложения
- **WHEN** в `registry.yaml` присутствует секция `web:`
- **THEN** обработка основной секции (релизы, ассеты, автодетект платформ) продолжает работать без изменений

### Requirement: Проект без релиза скрыт
Скачиваемое приложение из основной секции реестра, у которого нет ни одного GitHub-Release или у последнего релиза отсутствуют ассеты, MUST быть полностью скрыто на витрине (ни карточки, ни страницы). Это требование MUST NOT применяться к записям секции `web:`: веб-приложение публикуется без GitHub Release в соответствии с контрактом capability `store-web-apps`.

#### Scenario: Проект в разработке
- **WHEN** репозиторий в основной секции реестра содержит контракт, но не имеет релизов
- **THEN** на витрине нет ни карточки, ни страницы, ни упоминания этого приложения

#### Scenario: Первый релиз опубликован
- **WHEN** у ранее скрытого приложения появляется первый GitHub-Release с ассетами
- **THEN** после ближайшей синхронизации приложение появляется на витрине

#### Scenario: Веб-приложение без релиза
- **WHEN** запись секции `web:` указывает источник, в котором нет ни одного GitHub-Release
- **THEN** страница `/apps/<slug>/` и карточка веб-приложения публикуются на витрине
