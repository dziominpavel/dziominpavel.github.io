## Why

Витрина показывает только скачиваемые приложения, но часть инструментов владельца живёт в браузере и не имеет смысла как «загрузить файл»: у Benchmark — результаты прогонов LLM-арены, у InstagramTracker — аналитика подписчиков, которую вообще нельзя выгружать на сервер. Владелец запросил на витрине блок веб-приложений, которые открываются отдельными страницами внутри стора.

## What Changes

- Реестр (`registry.yaml`) получает секцию `web:` — записи веб-приложений со слагом, источником и метаданными карточки; запись НЕ требует GitHub Release, версии-файла и скриншотов (контракт источника — `index.html` + ресурсы, статика без серверной части).
- Генератор и CI публикуют статику веб-приложений в `_site/apps/<slug>/` — отдельные страницы с собственным URL, обратной навигацией в каталог и включением в sitemap; битая запись → skip + warning, сборка MUST NOT падать.
- Главная страница получает блок «Веб-приложения»: карточка с иконкой, описанием, датой обновления и primary-CTA «Открыть в браузере» (без версии/размера/счётчика скачиваний).
- **Веб-приложение 1 — InstagramTracker Web**: одностраничный анализер экспорта Instagram с пошаговой инструкцией (куда зайти, что выгрузить, куда загрузить), приёмом ZIP/папки/JSON-файлов через drag&drop и разбором строго в браузере — данные посетителя MUST не покидать устройство; дашборд с секциями аналитики, динамика — сравнение с предыдущим снимком, сохранённым локально.
- **Веб-приложение 2 — Benchmark Web**: статическая страница результатов прогонов из `data/index.json` репозитория Benchmark: таблица ELO-рейтинга, динамика рейтингов, лента последних прогонов, сводка — только чтение, без форм, админки и обновления данных со стороны посетителя.
- Всё хостится на том же origin (`dziominpavel.github.io`), без CDN и внешних зависимостей; язык витрины — русский.
- YandexMusicDownloader web **не входит** в изменение (скачивание из браузера невозможно статически — CORS/авторизация); другие проекты — по явному запросу владельца.

## Capabilities

### New Capabilities

- `store-web-apps`: публикация веб-приложений на витрине — контракт записей секции `web:`, сборка и хостинг страниц `/apps/<slug>/`, блок на главной, плюс поведение двух конкретных приложений (Instagram-анализер с инструкцией и приватностью, Benchmark-лидерборд только на чтение).

### Modified Capabilities

- `store-data-contract`: требование **«Реестр проектов в репозитории стора»** — реестр дополнительно содержит секцию `web:` со своим контрактом записей (MODIFIED); требование **«Проект без релиза скрыт»** — ограничивается скачиваемыми приложениями, запись веб-приложения публикуется без релиза (MODIFIED).
- `store-catalog`: требование **«Структура страниц»** — витрина дополнительно состоит из страниц веб-приложений `/<apps>/<slug>/` и блока «Веб-приложения» на главной (MODIFIED).

## Impact

- Стор: `generate.py` (новый тип записи, страницы `/apps/<slug>/`, секция главной), `registry.yaml` (секция `web:`), `.github/workflows` (получение статики веб-приложений), `tests/test_generate.py` и `tests/validate_site.py` (покрытие web-записей и страниц).
- Смежные репозитории (работа в рамках этого изменения): `instagram-tracker` — новая веб-страница анализера (`web/`), `Benchmark` — веб-страница лидерборда и публикация `data/index.json`.
- Зависимости: порядок архивации — после `add-app-store` (дельты MODIFIED по `store-catalog`/`store-data-contract` требуют существующих основных спеков); интеграция со счётчиком GoatCounter (задача 1.4) — не блокирует: веб-страницы получат счётчик из общей разметки, когда он появится.
- Не затрагивается: контракт скачиваемых приложений, release-скрипты, автодетект платформ, логика релизных данных.
