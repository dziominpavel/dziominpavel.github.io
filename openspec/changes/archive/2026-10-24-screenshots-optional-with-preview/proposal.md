# Proposal

## Why

Контракт требует 3–5 скриншотов, а генератор полностью скрывает приложение, если их меньше трёх. Из-за этого новое приложение не может попасть на витрину, пока владелец не подготовит три файла, а пять приложений до сих пор таскают нарисованные заглушки «Скриншот 1/3» — с квадратами вместо кириллицы и лишними ~84 КБ на страницу. Это одновременно блокирует запуск новых приложений и показывает посетителю фейковые скриншоты.

## What Changes

- Контракт смягчается: папка `screenshots/` становится опциональной и MAY содержать 0–5 изображений; 0, 1 и 2 скриншота — валидные состояния, приложение публикуется.
- Если подготовленных скриншотов нет, страница приложения показывает один блок «Превью» на HTML/CSS: без изображений, с сообщением, что скриншоты появятся позже. Галерея с фейковыми картинками не выводится.
- При 1–2 скриншотах галерея показывает только реальные изображения, без добивки до трёх.
- Если скриншотов больше пяти, публикуются первые пять, а в лог выводится предупреждение; приложение не скрывается.
- Из пяти репозиториев удаляются 15 файлов `*-placeholder.png` (GymProgress, VoiceMind, Wishlot, InstagramTracker, YandexMusicDownloader); заглушки больше не являются частью контракта.
- Обновляются валидация, тесты, README и контекст OpenSpec, где сейчас зафиксировано «3–5».
- В `CHANGELOG.md` появляется пользовательский пункт о публикации приложений без скриншотов.

Change выполняется после `optimize-image-loading` и использует его метаданные подготовленных превью: пустой блок показывается, когда не осталось ни одного пригодного изображения, а не только когда пуст исходный список.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `store-data-contract`: папка `screenshots/` становится опциональной, допустимое число изображений — 0–5; приложение без скриншотов больше не пропускается.
- `store-catalog`: добавляется блок «Превью» вместо галереи, когда у приложения нет ни одного подготовленного скриншота.

## Impact

- `generate.py` — валидация количества скриншотов, ветка fallback в рендере страницы приложения.
- `static/css/style.css` — оформление блока «Превью» в обеих темах.
- `tests/test_generate.py` — сценарии 0, 1–2 и >5 скриншотов, проверка отсутствия `<img>` в fallback.
- `README.md` — описание контракта без обязательных 3–5.
- `openspec/config.yaml` — контекст проекта: `screenshots/` 0–5, опционально.
- `CHANGELOG.md` — пользовательский блок `## [Unreleased]`.
- Пять репозиториев приложений — удаление 15 файлов-заглушек; `store.yaml`, `version` и релизы не меняются.
- Страницы пяти приложений теряют ~84 КБ фейковых изображений; новых зависимостей нет.
