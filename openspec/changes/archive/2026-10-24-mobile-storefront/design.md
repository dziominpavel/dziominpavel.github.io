# Design

## Context

Витрина — один статический CSS-файл `static/css/style.css` (mobile-first база
и точки перелома `min-width`), разметка собирается шаблонами в `generate.py`.
Сейчас мобильных правил почти нет: единственная `@media (max-width: 480px)`
уменьшает логотип hero до 64 px, а `@media (max-width: 560px)` переводит блок
«Об авторе» в колонку.

Что определяет подход:

- Страница приложения — grid `.app` из двух детей: `.app-main` (поток
  контента) и `aside.download`. На десктопе `grid-template-columns:
  minmax(0, 1fr) 340px`, блок скачивания — `position: sticky`.
- `.site-header-inner` и `.site-nav` используют `flex-wrap: wrap` без мобильной
  ветки, поэтому навигация уезжает на вторую строку.
- `.filters` — `inline-flex` с `flex-wrap: wrap`; при четырёх сегментах
  последний остаётся один.
- `.gallery .shots` — `repeat(auto-fill, minmax(170px, 1fr))`: при контейнере
  меньше 356 px остаётся одна колонка.
- Браузерных тестов в репозитории нет: `tests/validate_site.py` проверяет
  только статическую разметку. Остальное подтверждается прогоном в браузере
  с эмуляцией устройства.

## Goals / Non-Goals

**Goals:**

- Привести все страницы витрины к 360–430 CSS px без горизонтальной прокрутки.
- Сделать блок скачивания первым смысловым блоком после заголовка приложения
  на телефоне, не меняя десктопную раскладку.
- Сохранить требование спеки: логотип витрины рядом с названием сайта, а не
  вместо него.

**Non-Goals:**

- Редизайн десктопа и переверстка карточек каталога.
- Мобильное меню-гамбургер и любая логика на JavaScript ради раскладки.
- Изменение контракта `store.yaml`, `registry.yaml` и структуры данных.
- Мобильная адаптация зеркала Benchmark: это отдельный change `mobile-console`
  в репозитории Benchmark.

## Decisions

### D1. Плоская структура страницы приложения: заголовок → скачивание → контент

`APP_TEMPLATE` меняет обёртку: вместо `.app-main`, внутри которого лежит весь
контент, появляются три блока верхнего уровня — `.app-head`, `aside.download`
и `.app-body` с описанием, требованиями, «Что нового» и галереей.

```
<div class="app">
  <header class="app-head">…</header>
  <aside class="download">…</aside>
  <div class="app-body">…</div>
</div>
```

Мобильная раскладка — одна колонка, порядок в разметке и есть визуальный
порядок. Десктоп — две строки и две колонки:

```
.app { grid-template-columns: minmax(0, 1fr) 340px;
       grid-template-areas: "head download" "body download"; }
```

Почему так, а не `order`/`display: contents`:

- `order: -1` на `aside` поднимает его выше всего `.app-main`, то есть выше
  иконки и названия — не то, что нужно.
- `display: contents` на `.app-main` требует явного `order` каждому ребёнку и
  ломается, когда `requirements` или `whats-new` отсутствуют.
- Обёртка `.app-body` даёт ровно две строки сетки независимо от наличия
  необязательных блоков, поэтому `grid-template-areas` не создаёт пустых
  строк с лишними отступами и sticky-блок сохраняет область прилипания на всю
  высоту страницы.

Тест `tests/test_generate.py`, проверяющий порядок `app-desc → requirements →
whats-new → gallery`, продолжает проходить: все четыре блока остаются внутри
`.app-body` в прежнем порядке. Добавляется проверка, что `class="download"`
идёт в разметке после `class="app-head"` и до `class="app-desc"`.

### D2. Точки перелома: 480, 600, 1024

- `≤480 px` — шапка, hero, галерея.
- `≤600 px` — фильтр и минимальные области нажатия.
- `≥1024 px` — существующая десктопная сетка `.app` (не меняется).

Значения выбраны по фактическим замерам: четыре сегмента фильтра занимают
около 370 px и перестают помещаться в одну строку ниже ~440 px, поэтому 600 px
даёт запас на двузначные счётчики. Порог 480 px покрывает диапазон, где
`auto-fill minmax(170px, 1fr)` схлопывает галерею в одну колонку.

Новые правила добавляются отдельным блоком в конце `style.css` и не
переписывают mobile-first базу — это меньше риска для десктопа и проще
откатывается.

### D3. Шапка на узких экранах

- `.site-header-inner`: `flex-wrap: nowrap`, отступы `8px 12px`, зазор 8 px.
- `.brand`: шрифт `--fs-sm`, зазор 8 px, `min-width: 0`; текст названия
  оборачивается в `<span class="brand-text">` с `overflow: hidden;
  text-overflow: ellipsis; white-space: nowrap` — страховка для ширин ниже
  360 px, на целевых ширинах многоточия нет.
- `.brand-mark`: 26×26 px.
- `.site-nav a`: `min-height: 44px`, `display: inline-flex`, горизонтальный
  padding 8 px (6 px ниже 400 px), шрифт `--fs-sm` (`--fs-xs` ниже 400 px).
- `.theme-toggle`: 44×44 px.

Итоговая высота шапки: 44 px контента + 16 px отступов + 1 px границы = 61 px,
что укладывается в предел 64 px.

Почему не гамбургер-меню: четыре пункта помещаются в строку после сжатия
типографики, а скрытие навигации за кнопкой ухудшает доступность и требует JS.

### D4. Фильтр 2×2 вместо переноса и вместо горизонтальной прокрутки

```
.filters { display: grid; grid-template-columns: repeat(2, minmax(0, 1fr));
           width: 100%; border-radius: var(--r-md); }
.filter  { min-height: 44px; justify-content: center; }
.filters > .filter:last-child:nth-child(odd) { grid-column: 1 / -1; }
```

Селектор `:last-child:nth-child(odd)` растягивает последний сегмент на всю
ширину только при нечётном числе — это случай из спеки, когда секции `web:`
нет и остаются три сегмента.

Горизонтальная прокрутка сегментов отклонена: последний сегмент оказался бы
за краем экрана без визуальной подсказки. Перенос `flex-wrap` отклонён: именно
он даёт сироту «Web 2».

### D5. Галерея: две колонки на телефоне

```
@media (max-width: 480px) {
  .gallery .shots { grid-template-columns: repeat(2, minmax(0, 1fr));
                    gap: var(--sp-2); }
}
```

`minmax(0, 1fr)` вместо `1fr` обязателен: скриншоты — изображения с собственной
шириной, и без нулевого минимума колонка может распереть сетку. Пропорции
сохраняются за счёт `width: 100%; height: auto` у `.shot img`.

### D6. Hero: логотип 48 px и заголовок `--fs-xl`

При 360 px строка «логотип + заголовок» сейчас не помещается: 64 px логотипа,
16 px зазора и заголовок 34 px дают около 356 px при доступных 328 px.
Уменьшение логотипа до 48 px и заголовка до `--fs-xl` (24 px) даёт около
288 px — заголовок остаётся в одну строку рядом с логотипом, как требует
`store-catalog`.

### D7. Области нажатия

`min-height: 44px` добавляется ссылкам навигации, сегментам фильтра и
переключателю темы; кнопки скачивания уже имеют высоту около 51 px за счёт
`.btn-lg`. На десктопе размеры не меняются — правила живут только в
`max-width`-ветках.

### D8. Проверка результата

1. `python generate.py` собирает `_site/`.
2. Статическая проверка: `python tests/validate_site.py _site`.
3. Браузерная проверка на 360×740, 390×844 и 430×932 с эмуляцией устройства:
   `document.documentElement.scrollWidth <= window.innerWidth`, высота
   `.site-header` ≤ 64 px, число строк фильтра = 2, колонок галереи ≥ 2,
   `aside.download` выше `.app-desc` в визуальном порядке.
4. Повторная проверка на 1280×800: правая колонка и sticky-блок не изменились.

## Risks / Trade-offs

- **Порядок для скринридеров на десктопе**: блок «Скачать» теперь идёт в
  разметке раньше описания. → Смысловой порядок не хуже (главное действие
  раньше), визуальный порядок на десктопе прежний; `aria-label="Скачивание"`
  сохраняется.
- **Теснота шапки на 360 px**: сжатие типографики может дать перенос при
  нестандартном системном шрифте. → `nowrap` плюс многоточие на названии сайта
  гарантируют отсутствие горизонтальной прокрутки; проверка на 360 px входит
  в приёмку.
- **Двухколоночная галерея на 360 px**: снимки становятся мелкими
  (около 150 px). → Это превью; полный размер доступен по клику, а длина
  страницы сокращается почти вдвое по сравнению с одной колонкой.
- **Кэш CSS на GitHub Pages**: после деплоя возможен кратковременный разнобой
  разметки и стилей. → Изменение чисто косметическое, без изменения данных;
  разнобой исчезает после обновления кэша.

## Migration Plan

Отдельной миграции не требуется: статическая сборка, данных и внешних
контрактов изменение не касается. Откат — revert коммита и повторный деплой.
