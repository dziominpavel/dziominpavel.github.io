# Proposal: show-whats-new-on-app-pages

## Why

Страница приложения рассказывает, *что* скачать (версия, размер, кнопки, скриншоты), но не отвечает на вопрос «а что изменилось?» — посетитель не видит, ради чего обновляться. При этом витрина уже получает `body` последнего релиза из GitHub API, а тело релиза — это как раз тот краткий пользовательский блок изменений, который release-скрипт формирует из секции changelog (capability `app-release-pipeline`). Данные под рукой, показать их на странице — прямая задача генератора.

## What Changes

- Страница приложения `/<slug>/` получает секцию «Что нового в vX.Y.Z» в основном потоке (`app-main`): после описания и системных требований, перед галереей скриншотов.
- Источник текста — поле `body` последнего GitHub-Release (уже запрашиваемый `releases/latest`); новых обращений к API не добавляется.
- Содержимое тела релиза рендерится по его реальному формату: жирные метки категорий (`**Добавлено**`) — заголовками блоков, буллеты `- ...` — списком; произвольный текст старых релизов (свободная проза) — экранированными абзацами. Всё экранируется, вёрстка не ломается.
- Секция сопровождается ссылкой «Все изменения» на страницу релизов репозитория.
- При пустом теле релиза секция MUST отсутствовать, страница рендерится как раньше.
- Секция показывается только на страницах скачиваемых приложений; на карточках главной и страницах веб-приложений — нет.
- Обновление — без дополнительных действий: тело релиза подхватывается ближайшей сборкой витрины наравне с версией и размером.

### Modified Capabilities

- `store-catalog`: новая секция «Что нового» на странице приложения — требование о блоке (источник, формат рендера, экранирование, отсутствие при пустом теле) + уточнение требования «Структура страниц»: сценарий «Страница приложения» включает блок изменений последнего релиза.

## Impact

- `generate.py`: `release_card()` — добавить поле `notes` из `body` релиза; новая функция рендера секции; подстановка в `APP_TEMPLATE` (сейчас `{description}`, `{requirements}`, `{gallery}`).
- `static/css/style.css`: оформление секции (заголовки-метки, список, ссылка) в обеих темах, контраст AA.
- `tests/test_generate.py`: тесты рендера блока (метки+буллеты, проза, пустое тело, экранирование), позиция на странице.
- `openspec/specs/store-catalog/spec.md` — дельтой этого change.
- Потребители контракта и `store-data-contract` не меняются: `body` — штатное поле GitHub Release, ничего нового от приложений не требуется.
