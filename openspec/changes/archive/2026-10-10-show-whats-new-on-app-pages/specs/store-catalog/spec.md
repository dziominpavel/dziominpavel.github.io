## ADDED Requirements

### Requirement: Блок «Что нового» на странице приложения
Страница скачиваемого приложения MUST показывать секцию изменений последнего релиза — краткий пользовательский блок, опубликованный телом GitHub-Release. Источник текста — поле `body` последнего релиза, получаемого из того же ответа GitHub API, что и версия, размер и ассеты; отдельных запросов к API ради секции MUST NOT добавляться. Секция MUST размещаться в основном потоке страницы после описания и системных требований и перед галереей скриншотов и сопровождаться заголовком с версией релиза и ссылкой «Все изменения» на страницу релизов репозитория.

Содержимое тела релиза MUST рендериться по его реальному формату: строка-жирная метка категории (`**Добавлено**` и аналоги) — заголовком блока, буллет (`- ...`) — элементом списка, прочие строки (свободная проза исторических релизов) — абзацами. Весь текст MUST экранироваться: тело релиза — данные внешнего источника, и его разметка MUST отображаться как текст, а не исполняться. Секция MUST обновляться наравне с версией и размером — ближайшей сборкой витрины после публикации релиза.

Если тело релиза пустое (или состоит только из пробельных символов), секция MUST отсутствовать на странице, а сама страница MUST рендериться без изменений и без предупреждений. Секция MUST выводиться только на страницах скачиваемых приложений; карточки главной страницы и страницы веб-приложений (`/apps/<slug>/`) оставаться без неё.

#### Scenario: Тело релиза с метками и буллетами
- **WHEN** тело последнего релиза состоит из жирных меток категорий и буллетов
- **THEN** страница приложения показывает секцию «Что нового» с версией релиза: метки выводятся заголовками соответствующих блоков, буллеты — списком, рядом есть ссылка «Все изменения» на страницу релизов репозитория

#### Scenario: Старый релиз со свободной прозой
- **WHEN** тело последнего релиза (опубликованное до введения формат-контракта) состоит из связных строк без меток и буллетов
- **THEN** текст выводится абзацами без списков, страница рендерится без ошибок

#### Scenario: Пустое тело релиза
- **WHEN** у последнего релиза нет текста тела или оно состоит только из пробельных символов
- **THEN** секция «Что нового» на странице отсутствует, остальное содержимое страницы не меняется

#### Scenario: Спецсимволы в теле релиза
- **WHEN** тело релиза содержит символы разметки (`<`, `&`, `"`), жирные метки и буллеты одновременно
- **THEN** все символы выводятся как видимый текст, разметка страницы не нарушается, XSS через тело релиза невозможен

#### Scenario: Web-приложение и карточка главной
- **WHEN** генератор рендерит страницу веб-приложения `/apps/<slug>/` и карточки главной
- **THEN** секция «Что нового» в их разметке отсутствует

## MODIFIED Requirements

### Requirement: Структура страниц
Витрина MUST состоять из: главной страницы (единая лента карточек — скачиваемые приложения и web-карточки вперемешку по убыванию даты + фильтр каталога с сегментами Все, Android, Windows, Web), отдельной страницы на каждое скачиваемое приложение (`/<slug>/`), страниц веб-приложений (`/apps/<slug>/`), страницы «О проекте». Язык витрины — только русский. Навигация между страницами MUST быть доступна с каждой страницы; шапка каждой страницы MUST содержать логотип витрины (ссылку на главную) рядом с названием сайта. Все карточки главной MUST идти в одной ленте по убыванию даты обновления (скачиваемые — по дате публикации релиза, web — по дате обновления данных); порядок записей в `registry.yaml` MUST определять только состав каталога, а не порядок карточек.

#### Scenario: Фильтр по платформе
- **WHEN** посетитель выбирает платформу Android на главной
- **THEN** отображаются только карточки приложений, у которых есть ассеты Android; web-карточки скрыты

#### Scenario: Сегмент Web
- **WHEN** посетитель выбирает сегмент Web на главной
- **THEN** в единой ленте отображаются только web-карточки, карточки скачиваемых приложений скрыты

#### Scenario: Страница приложения
- **WHEN** посетитель открывает `/<slug>/`
- **THEN** он видит: полное описание, обязательный блок системных требования (если задан), блок изменений последнего релиза («Что нового»), галерею скриншотов, версию, размер, дату, счётчик скачиваний, кнопки скачивания по каждой доступной платформе, ссылку «Исходники» на GitHub-репозиторий

#### Scenario: Страница веб-приложения
- **WHEN** посетитель открывает `/apps/<slug>/`
- **THEN** он видит веб-приложение и навигацию обратно в каталог; страница включена в sitemap

#### Scenario: Web-карточки в общей сетке
- **WHEN** в реестре есть записи секции `web:`
- **THEN** на главной странице в единой ленте среди карточек скачиваемых отображаются web-карточки по их дате обновления; они видны в сегментах Все и Web и скрыты в сегментах Android/Windows

#### Scenario: Порядок карточек
- **WHEN** приложения перечислены в `registry.yaml` в произвольном порядке, а даты их релизов и обновлений различаются
- **THEN** на главной все карточки идут от самой свежей даты к старой вперемешку, без группировки по типу; добавление новой записи в реестр MUST NOT менять порядок остальных карточек
