## Purpose

Публикация веб-приложений на статической витрине «Мои приложения»: контракт записей в реестре, сборка и хостинг страниц `/apps/<slug>/`, карточки на главной странице, а также поведение размещённых веб-приложений (анализер InstagramTracker, лидерборд Benchmark).

## ADDED Requirements

### Requirement: Реестр веб-приложений
`registry.yaml` MUST содержать опциональную секцию `web:` — записи веб-приложений. Ключ записи MUST соответствовать паттерну `[a-z0-9-]` и служить слагом страницы веб-приложения (`/apps/<key>/`). Запись MUST указывать источник статики (репозиторий-источник) и метаданные карточки (название, описание; иконка опциональна). Запись секции `web:` MUST NOT требовать GitHub Release, файла `version` и скриншотов. Добавление веб-приложения в стор MUST требовать только добавления одной записи в секцию `web:` без правок кода стора.

#### Scenario: Добавление третьего веб-приложения
- **WHEN** владелец добавляет новую запись в секцию `web:`
- **THEN** после ближайшей сборки появляются страница `/apps/<slug>/` и карточка на главной, код стора не изменялся

#### Scenario: Некорректный ключ веб-записи
- **WHEN** ключ записи в секции `web:` не соответствует `[a-z0-9-]`
- **THEN** запись отклоняется с предупреждением в логе; остальные записи витрины обрабатываются

### Requirement: Публикация статики веб-приложений
Сборка витрины MUST копировать статику каждой валидной записи `web:` в `_site/apps/<slug>/`, чтобы страница открывалась по прямому URL и полностью работала без серверной части. Страница веб-приложения MUST содержать навигацию обратно в каталог. Язык страницы — только русский. Страница MUST работать без внешних CDN и сторонних хостингов (все ресурсы — с-origin витрины). Sitemap MUST включать страницы веб-приложений.

#### Scenario: Прямая ссылка на страницу
- **WHEN** посетитель открывает `/apps/<slug>/` по прямой ссылке
- **THEN** страница отдаётся, содержит ссылку обратно в каталог и включена в sitemap

#### Scenario: Источник недоступен или битый
- **WHEN** статику получить не удалось (в источнике нет `index.html`, ошибка получения репозитория)
- **THEN** сборка продолжается с предупреждением в логе, страница и карточка этого веб-приложения пропускаются, остальная витрина публикуется; сборка MUST NOT падать

### Requirement: Web-карточки на главной странице
Главная страница MUST показывать карточки веб-приложений в общей сетке сразу после карточек скачиваемых приложений (без отдельной секции и отдельного заголовка): иконка (при отсутствии — буквенная заглушка), название, описание, дата обновления данных и primary-действие «Открыть в браузере» со ссылкой на `/apps/<slug>/`. Макет web-карточки MUST быть консистентен с карточкой скачиваемого приложения. Карточка веб-приложения MUST NOT требовать версию, размер релиза и счётчик скачиваний.

#### Scenario: Два веб-приложения на витрине
- **WHEN** в секции `web:` две записи
- **THEN** в общей сетке после карточек скачиваемых видны две web-карточки, каждая ведёт на свою страницу `/apps/<slug>/`

#### Scenario: Иконка веб-приложения отсутствует
- **WHEN** у записи нет файла иконки
- **THEN** карточка показывает буквенный плейсхолдер; сборка MUST NOT падать

### Requirement: InstagramTracker Web — анализер экспорта с инструкцией
Страница `/apps/instagram-tracker/` MUST содержать пошаговую инструкцию: куда зайти в Instagram, какие данные выгрузить (формат JSON) и куда загрузить результат. Страница MUST принимать данные экспорта через drag&drop или выбор файла: ZIP-архив, папку либо отдельные JSON-файлы. Разбор экспорта и построение дашборда MUST выполняться целиком в браузере посетителя: содержимое экспорта MUST NOT передаваться ни в один сетевой запрос (допустимы только загрузка статики страницы и счётчик посещений витрины). Результат — дашборд: счётчики подписчиков/подписок и секции аналитики выгрузки; если локально сохранён предыдущий снимок — дополнительно динамика (новые/потерянные). Ошибка разбора MUST показываться понятным сообщением без разрушения страницы.

#### Scenario: Пошаговая инструкция
- **WHEN** посетитель открывает страницу анализера
- **THEN** он видит шаги: куда зайти, что выгрузить, куда загрузить данные

#### Scenario: Загрузка экспорта
- **WHEN** посетитель перетаскивает ZIP-архив экспорта (или папку/JSON-файлы) на страницу
- **THEN** дашборд с аналитикой строится локально, без перезагрузки страницы и без отправки данных на сервер

#### Scenario: Файл не из экспорта Instagram
- **WHEN** посетитель загружает файл не той структуры
- **THEN** страница показывает понятное сообщение об ошибке и остаётся работоспособной

### Requirement: Benchmark Web — статические результаты только на чтение
Страница `/apps/benchmark/` MUST отображать результаты прогонов из `data/index.json` репозитория Benchmark: таблицу ELO-рейтинга моделей (место, название, провайдер, рейтинг, статистика игр), динамику рейтингов, сводку и ленту последних прогонов, а также дату обновления данных. Страница MUST работать только на чтение: формы ввода, редактирование моделей и управление прогонами на ней отсутствуют. Данные обновляются только при сборке витрины.

#### Scenario: Открытие страницы рейтинга
- **WHEN** посетитель открывает `/apps/benchmark/`
- **THEN** он видит ELO-таблицу моделей, сводку прогонов и дату обновления; форм и элементов управления данными на странице нет

#### Scenario: Обновились данные прогонов
- **WHEN** при сборке витрины `data/index.json` в репозитории Benchmark обновился
- **THEN** после ближайшего деплоя страница показывает обновлённые цифры без каких-либо действий посетителя
