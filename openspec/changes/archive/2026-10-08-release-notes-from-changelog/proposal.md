# Proposal: release-notes-from-changelog

## Why

Тело GitHub-Release у **всех** релизов **всех** 7 проектов пустое: `gh release create $Tag --title $Tag` вызывается без `--notes`, поэтому на странице релиза — только заголовок и Assets, а написанный вручную changelog остаётся в `CHANGELOG.md` репозитория и нигде больше не виден (витрина его не читает). Вдобавок секции changelog пишутся «простынями» на 8–10 КБ с change-id, числами тестов и метриками — даже если бы текст попал в релиз, читать его скачивающему APK человеку неудобно.

## What Changes

- **Заметки релиза берутся из changelog.** Release-скрипт вырезает из `CHANGELOG.md` секцию свежей версии и передаёт её в `gh release create --notes-file`; тегу отдаётся то же тело. Заметки — блок секции **до первой строки `###`** (для исторических секций без `###` — вся секция).
- **Норма оформления секции.** Секция `[Unreleased]` и свёрнутая в неё версионная секция начинаются с пользовательского саммари (2–5 буллетов «что заметно пользователю») до первой категории `###`; инженерские детали (change-id, тесты, метрики) остаются под `###`. Один текст — два среза, без параллельного написания.
- **Гейт на подготовке.** `release.ps1 -Prepare` отказывается сворачивать секцию, если до первой `###` нет текста — иначе релиз снова уехал бы с пустым телом.
- **Кодировка.** Временный файл заметок пишется UTF-8 без BOM; чтение секции — через `Read-Changelog` (`[System.IO.File]::ReadAllText`), а не через консольный вывод `git show`.
- **Рассылка.** `$SCRIPT_VERSION` 1.2.0 → 1.3.0, копии обновляются `sync-release.ps1` по всем 7 репозиториям.
- **Бэкфилл.** 11 уже опубликованных релизов (FogMap 3, YandexMusicDownloader 2, ChargeForecast 2, по 1 в GymProgress, VoiceMind, Wishlot, InstagramTracker) получают тело — текст секции целиком, через `gh release edit --notes-file`. `latest` при этом не меняется, витрина не съезжает.
- **Уточнение политики.** Секции версий, сложившиеся до внедрения release-скрипта (FogMap 1.0.0–1.5.0), сохраняются как до-релизная история; «сборочные номера, не бывшие релизами» означают номера вида `x.y.z.N` и `base.count-gsha`, а не такие секции. История не переписывается.
- **Гигиена FogMap.** Удаляется второй `## [Unreleased]` посреди `CHANGELOG.md` — два буллета-дубля, чьи change-id уже описаны в секциях `1.2.0` и `1.5.0`; блок невидим для конвейера и никогда не будет выпущен.
- **Тесты и доки.** Фикстуры `tests/test_release_phases.py`, дополняющие Unreleased только категориями `###`, получают саммари; добавляются проверки наличия заметок и гейта. Норма попадает в `docs/versioning.md` и `docs/agents-versioning-block.md` (раскатывается в AGENTS дочерних проектов), пункт — в `## [Unreleased]` changelog корня.

**BREAKING** не требуется: изменение расширяет публикуемый контент и ужесточает подготовку релиза, старое поведение (пустое тело) не поддерживается.

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `openspec/specs/app-release-pipeline/spec.md`: новое требование «Заметки релиза формируются из секции changelog» (блок до `###`, UTF-8 без BOM, `--notes-file`, тело тега); новое требование «Подготовка требует пользовательского саммари» (гейт в `-Prepare`).
- `openspec/specs/versioning-policy/spec.md`: новое требование «Секция changelog начинается с пользовательского саммари»; уточняющий сценарий в существующем требовании «Changelog обязателен в каждом проекте» про до-релизную историю и сборочные номера.

## Impact

- **Код:** `scripts/release.ps1` (эталон, корень) — вырезание секции, `--notes-file`, тело тега, бамп версии скрипта; `scripts/sync-release.ps1` — рассылка; `tests/test_release_phases.py` — фикстуры и 2 новых теста.
- **Репозитории:** копии `release.ps1` в 7 дочерних проектах (FogMap, GymProgress, VoiceMind, Wishlot, YandexMusicDownloader, ChargeForecast, InstagramTracker) — только рассылкой, без ручных правок.
- **Документация:** `docs/versioning.md`, `docs/agents-versioning-block.md`, `CHANGELOG.md` корня, `CHANGELOG.md` FogMap (удаление дубля секции).
- **GitHub:** 11 существующих релизов получают тело (бэкфилл); витрина (`generate.py`, `releases/latest`) не затрагивается — `gh release edit` не меняет `latest`.
- **Не затрагивается:** формат ассетов, имена тегов, порядок фаз, порядок `release.ps1 -Prepare` → сборка → `release.ps1`.
