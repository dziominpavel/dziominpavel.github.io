# Proposal: check-data-updated-consistency

## Why

Дата web-карточки источника с объявленным `data:` берётся из поля `updated` файла данных (`generate.py:371`), но ничто не сверяет это поле с реальным последним коммитом этого же файла. Если пайплайн источника допишет данные и забудет обновить `updated` (или обновит `updated`, не меняя данных), витрина будет молча показывать дату, которая не соответствует тому, что отдаёт страница. Наблюдение по Benchmark: `updated = 2026-10-06` совпадало с последним коммитом `data/` — но это совпадение ничем не гарантировано, и сейчас заметить расхождение можно только прочитав код генератора и сравнив даты руками.

## What Changes

- При сборке витрины генератор для каждой web-записи с `data:` сверяет календарную дату UTC поля `updated` с датой последнего коммита, тронувшего этот файл данных (GitHub API, тот же механизм, что уже используется для коммит-даты `web/`).
- Расхождение дат MUST печататься как `[WARN]` в лог сборки с указанием слага, значения `updated` и даты коммита. Дата карточки, содержимое статики и код возврата сборки при этом MUST NOT меняться — предупреждение наблюдательное, оно не чинит источник и не валит витрину.
- Если дату коммита получить не удалось (ошибка API, пустой ответ), сверка MUST пропускаться без предупреждения, чтобы лог не шумел при недоступном API; сборка и дата карточки при этом не меняются.

Изменений в контракте источников (`registry.yaml`, поле `data:`, формат `updated`) нет. Поведение карточки (источник даты) не меняется — меняется только видимость его рассинхрона.

### Modified Capabilities

- `store-web-apps`: добавляется требование о сверке поля `updated` объявленного файла данных с датой последнего коммита этого файла и о наблюдательном характере расхождения (WARN без изменения даты карточки и без остановки сборки). Существующее правило источника даты web-карточки сохраняется без изменений.

## Impact

- `generate.py` — ветка `data_file` в `collect_web_projects` (`generate.py:364-394`) и хелпер получения коммит-даты по пути (`fetch_web_commit_date`, `generate.py:295`).
- `tests/test_generate.py` — новые проверки: расхождение печатает WARN, совпадение молчит, недоступность API не шумит; существующие проверки даты карточки должны остаться зелёными.
- Лог сборки в GitHub Actions (`build-site`) — появляется предупреждение при рассинхроне источника; на статику, деплой и на потребителей контракта не влияет.
- Спека `store-web-apps` — один новый requirement с тремя сценариями.
