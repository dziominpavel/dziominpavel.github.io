## Why

Счётчик «Скачиваний» на карточке и странице приложения берёт `download_count` только из последнего релиза (`releases.latest`). Поскольку GitHub считает скачивания в разрезе ассетов конкретного релиза, каждая новая версия стартует с нуля и счётчик видимо «обнуляется», хотя приложение за всё время скачали существенно больше. Витрина занижает реальную популярность и противоречит ожиданию владельца: счётчик должен отражать приложение, а не его последнюю сборку.

## What Changes

- Счётчик скачиваний становится суммой по **всем опубликованным релизам** приложения (привязка к приложению), а не только по последнему.
- В сумму включаются все опубликованные релизы, в том числе prerelease; **draft-релизы исключаются** (не опубликованы — их скачивания не считаются).
- Версия, размер, дата, ссылки на скачивание и блок «Что нового» **остаются** привязанными к последнему релизу (`releases.latest`) — без изменений.
- Обход всех релизов выполняется постранично с верхним лимитом страниц, чтобы репозиторий с сотнями релизов не раздувал сборку; счёт не падает при недоступности списка релизов.

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `store-catalog`: требование «Карточка приложения» — уточняется область счётчика скачиваний: он MUST отображаться как сумма скачиваний по всем опубликованным релизам приложения (включая prerelease, исключая draft), а не только по последнему релизу.

## Impact

- `generate.py`: `release_card()` больше не выводит `downloads` из единственного релиза; добавляется получение всех опубликованных релизов репозитория и суммирование `download_count` их ассетов. Затронуты `fetch_latest_release` / `release_card` и сбор каталога.
- `openspec/specs/store-catalog/spec.md`: требование «Карточка приложения» и его сценарий «Счётчик скачиваний» уточняются (дельта в этом change).
- `tests/test_generate.py`: фикстура пинает однорелизный подсчёт — пойдёт за кодом; потребуются кейсы на сумму по нескольким релизам, включение prerelease и исключение draft.
- GitHub API: добавляется пагинированный запрос списка релизов на каждый проект (нужен токен `GITHUB_TOKEN` в CI ради лимита; обход ограничен по числу страниц).
- Контракт данных приложений (`store.yaml`, релизы источников) **не меняется** — `store-data-contract` остаётся соблюдённым (счётчик по-прежнему из GitHub Releases, а не из `store.yaml`).
