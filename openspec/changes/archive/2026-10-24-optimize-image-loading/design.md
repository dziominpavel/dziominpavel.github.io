# Design

## Context

См. `proposal.md` — Why. Текущее состояние, важное для подхода:

- `generate.py` копирует исходные файлы из клона репозитория в `_site` через `shutil.copy2`: иконку — как `icon<ext>`, скриншоты — в `screenshots/` под исходными именами (строки 1091–1103).
- `gallery_html()` (строки 771–782) выводит `<img src="screenshots/<имя>">` без `srcset`/`sizes`/`width`/`height`, с `loading="lazy"`.
- `app_icon_html()` (строки 643–648) выводит `<img class=... src="<slug>/icon<ext>">` с `width="96" height="96"`; CSS задаёт 56 px для `.card-icon` и 96 px для `.app-icon`.
- Галерея — сетка `repeat(auto-fill, minmax(170px, 1fr))`, то есть ячейка примерно 170–260 px; исходники — 1080×2400 PNG.
- GitHub Pages отдаёт статику с `Cache-Control: max-age=600` и не оптимизирует изображения.
- В CI (`build.yml`) ставятся только `pyyaml` и `flask`; Pillow уже используется офлайн-скриптом `scripts/gen-app-icons.py`, но в CI отсутствует.
- `render_site()` полностью удаляет `out_dir` перед сборкой (строки 1029–1030), поэтому старые исходники не задержатся в `_site` после перехода.

## Goals / Non-Goals

**Goals:**

- Сократить вес картинок на странице приложения и главной в разы, не меняя контракт приложений.
- Публиковать только производные, сохраняя исходники источником правды в репозиториях приложений.
- Сохранить текущую вёрстку, лайтбокс и буквенный плейсхолдер иконки.
- Не ронять сборку из-за одного битого изображения.

**Non-Goals:**

- Менять `store.yaml`, `screenshots/`, `version` или форматы исходников в репозиториях приложений.
- Поддержка приложений без скриншотов — это отдельный change.
- AVIF, `<picture>` с PNG-fallback, генерация OG-картинок и обложек карточек.
- Управление кэшированием GitHub Pages: заголовки задаёт хостинг.

## Decisions

### D1. Формат и качество: WebP, без PNG-fallback

Скриншоты кодируются в WebP с `quality=80` и `method=6`; иконки — с `quality=85` (альфа-канал сохраняется). PNG-fallback не делаем: WebP поддерживается подавляющим большинством браузеров, а `<picture>` удваивает объём сборки и усложняет разметку. AVIF даёт ещё 10–15 % экономии, но требует более свежего Pillow и даёт меньше выигрыша, чем сам переход с PNG; оставляем на будущее.

Альтернативы: JPEG (хуже для UI-скриншотов с текстом и прозрачностью), PNG (не даёт выигрыша), AVIF (сложнее и незначительно лучше WebP на этих изображениях).

### D2. Ширины: 540/1080 для скриншотов, 96/192 для иконок

540 px покрывает ячейку 170–260 px при DPR 2; 1080 px — лайтбокс и DPR 3. Для иконок 96 px покрывает показ 56 px при DPR 2, 192 px — показ 96 px при DPR 2. Третью ширину не вводим: выигрыш мал, а время сборки и число файлов растут.

Альтернативы: 360/720 (меньше запас для DPR 3 и будущей сетки), 720/1440 (тяжелее без заметной пользы).

### D3. Имена производных: индекс + ширина

Выходные имена строятся по порядку отсортированного списка: `screenshots/shot-01-540.webp`, `shot-01-1080.webp`; иконки — `icon-96.webp`, `icon-192.webp`. Индекс исключает коллизии имён (`01.png` и `01.jpg`) и делает набор детерминированным. Исходное имя в URL не нужно.

Альтернативы: сохранять stem исходника (риск коллизий и странных имён), content hash в имени (усложняет HTML и очистку; при `max-age=600` не даёт ощутимой пользы).

### D4. Пайплайн живёт в `generate.py` и работает до рендера HTML

Добавляются небольшие функции: подготовка производных скриншота/иконки, выбор `sizes`, рендер `<img>`. Подготовка выполняется один раз в начале `render_site()` — после очистки `out_dir` и до вызова `card_html()`/`app_icon_html()`/`gallery_html()`. Производные пишутся в `_site/<slug>/`, а метаданные (пути вариантов, ширина и высота) складываются в карточку; разметка уже использует готовые значения. Старый блок `shutil.copy2` для иконки и скриншотов удаляется. Отдельный скрипт или предварительно закоммиченные производные не нужны: сборка и так клонирует репозитории и удаляет `out_dir`.

Альтернативы: отдельный шаг CI (лишняя точка отказа), коммит производных в стор (дублирование и устаревание), генерация после рендера HTML (потребовала бы повторного прохода по страницам).

### D5. Разметка галереи

```html
<a class="shot" href="screenshots/shot-01-1080.webp" target="_blank" rel="noopener">
  <img src="screenshots/shot-01-540.webp"
       srcset="screenshots/shot-01-540.webp 540w,
               screenshots/shot-01-1080.webp 1080w"
       sizes="(max-width: 520px) 90vw, (max-width: 900px) 45vw, 240px"
       width="540" height="1200"
       alt="Скриншот ..." loading="lazy" decoding="async">
</a>
```

`sizes` — приближение под текущую сетку; точность проверим на 360/768/1280 px. В CSS добавляется `height: auto` для `.shot img`, чтобы атрибут `height` не растягивал изображение при `width: 100%`.

### D6. Разметка иконок

```html
<img class="card-icon" src="fogmap/icon-96.webp"
     srcset="fogmap/icon-96.webp 96w, fogmap/icon-192.webp 192w"
     sizes="56px" width="96" height="96" alt="Иконка ...">
```

На странице приложения `sizes="96px"`. Иконки грузятся без `loading="lazy"`: они выше сгиба и весят 2–5 КБ. Буквенный плейсхолдер остаётся без изменений.

### D7. Устойчивость и безопасность

Декодирование и кодирование каждого файла оборачивается в `try/except` (`UnidentifiedImageError`, `OSError`, `DecompressionBombError`). Битый скриншот пропускается с `[WARN]` в stderr; битая иконка помечается как отсутствующая и даёт буквенный плейсхолдер. Для защиты от «бомб» используется встроенный лимит Pillow; предупреждение о превышении лимита трактуется как ошибка изображения локально, без глобального изменения настроек процесса.

### D8. Зависимость и тесты

Pillow добавляется в шаг `pip install` в `build.yml`; в README появляется строка про локальную установку. Отдельный `requirements.txt` не вводим, чтобы не расширять изменение. Тесты используют Pillow для генерации валидных фикстур (например, 108×240 PNG) вместо байтов `b"\x89PNG fake"`; проверяются имена и размеры производных, атрибуты разметки, отсутствие исходников в `_site` и сценарий битого файла. Проверка «файл стал меньше» не используется как критерий — она нестабильна на крошечных фикстурах.

## Risks / Trade-offs

- **Старые браузеры без WebP** → целевая аудитория витрины — современные браузеры; при необходимости fallback добавляется отдельным change.
- **Потеря качества на текстовых скриншотах при 540 px/q80** → 540 px показывается в ячейке ~1×—2×, а полный просмотр идёт через 1080 px; после реализации визуально сверить FogMap и при необходимости поднять quality до 82–85.
- **Неточный `sizes` приведёт к выбору 1080 px там, где хватит 540** → проверить на трёх ширинах; `sizes` — подсказка, а не жёсткое правило.
- **Время сборки вырастет** → 7 приложений × 3 скриншота + иконки; декодирование/кодирование занимает секунды, тогда как клонирование репозиториев уже доминирует. При росте каталога можно кэшировать по хешу исходника.
- **Pillow отсутствует локально** → сборка/тесты упадут с понятной ошибкой импорта; README и CI закрывают сценарий.
- **CSS и атрибуты `width`/`height` конфликтуют** → `height: auto` для `.shot img`; иконки уже имеют фиксированные CSS-размеры.

## Migration Plan

1. Влить change и задеплоить обычной сборкой: `render_site()` удаляет `_site`, поэтому исходные PNG исчезнут из артефакта автоматически.
2. Проверить на живой странице FogMap: галерея открывается, лайтбокс ведёт на 1080 WebP, иконка на главной и странице отображается.
3. Откат — revert коммита и повторная сборка; данные и контракт приложений не меняются, миграция не требуется.
