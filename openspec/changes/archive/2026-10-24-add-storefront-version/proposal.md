# Proposal

## Why

Витрина — единственный проект владельца без собственной версии: в `versioning.yaml` она числится статическим треком, файла `version` нет, тегов и GitHub Releases нет. Из-за этого нельзя сказать, какая версия сайта сейчас в проде, а на странице «О проекте» нет истории версий, хотя у всех приложений каталога версия и теги есть.

## What Changes

- Витрина переводится со статического трека на релизный: добавляется файл `version` с первой версией `1.0.0`, запись `storefront` в `versioning.yaml` получает `track: release` и `version_file: version`.
- Первый релиз оформляется тегом `v1.0.0` и GitHub Release с пользовательскими заметками из changelog; release-скрипт и артефакты не вводятся — публикация вручную, как у Benchmark.
- Внизу страницы «О проекте» выводится версия витрины в формате `X.Y.Z` и ссылка на историю версий (GitHub Releases).
- Версия читается генератором из файла `version`; при отсутствии или невалидном значении строка не выводится, сборка не падает.
- На главной и страницах приложений версия витрины не дублируется.
- Обновляются тесты, README, контекст OpenSpec и changelog; в `versioning-policy` убирается пример витрины как статического проекта.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `store-catalog`: требование к содержимому страницы «О проекте» дополняется версией витрины и ссылкой на историю версий внизу страницы.
- `versioning-policy`: требование «Два трека проектов» больше не приводит витрину как пример статического трека; добавляется сценарий перехода витрины на релизный трек.

## Impact

- Новый файл `version` (1.0.0), запись `storefront` в `versioning.yaml`.
- `generate.py` — чтение версии и передача её в шаблон «О проекте».
- `static/css/style.css` — строка версии внизу страницы.
- `tests/test_generate.py` — версия есть/нет, позиция внизу, отсутствие на других страницах.
- `README.md`, `CHANGELOG.md`, `openspec/config.yaml`.
- Git-тег `v1.0.0` и GitHub Release витрины; контракт приложений и их репозитории не меняются.
