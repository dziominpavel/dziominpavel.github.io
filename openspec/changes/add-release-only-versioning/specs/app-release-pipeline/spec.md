## Purpose

Единый release-процесс всех приложений: как из исходников получается опубликованный GitHub-Release с ассетами, доступными для скачивания со витрины, при минимальном участии владельца, и почему релизный процесс является единственным событием, повышающим версию.

## ADDED Requirements

### Requirement: Подготовка релиза производит бамп версии
Release-скрипт в фазе подготовки MUST классифицировать содержимое секции `## [Unreleased]` файла `CHANGELOG.md`, определить уровень новой версии по наивысшему накопленному уровню, записать новый номер в файл `version` и свернуть секцию `[Unreleased]` в версионную секцию вида `## [X.Y.Z] — дата (УРОВЕНЬ)`. Подготовка MUST выполняться до сборки ассетов, чтобы в артефакты запеклась новая версия. Подготовка MUST NOT создавать тег, релиз или публикацию. Повышение версии вне релизного процесса MUST NOT выполняться другим механизмом.

#### Scenario: Релиз с накопленными изменениями
- **WHEN** владелец запускает подготовку при непустой секции `[Unreleased]`
- **THEN** файл `version` содержит новый номер, секция `[Unreleased]` заменена версионной секцией, тег и релиз НЕ созданы; последующая сборка запекает новый номер в артефакты

#### Scenario: Секция Unreleased пуста
- **WHEN** подготовка запущена, а секция `[Unreleased]` отсутствует или пуста
- **THEN** скрипт MUST завершиться с понятной ошибкой «нет накопленных изменений», а файл `version` и `CHANGELOG.md` MUST остаться без изменений

### Requirement: Публикация требует проведённой подготовки и чистого дерева
Release-скрипт в фазе публикации MUST отказаться, если секция `[Unreleased]` непуста (подготовка не выполнена). Публикация MUST требовать, чтобы рабочее дерево не содержало незакоммиченных изменений, кроме файлов бампа (`version` и `CHANGELOG.md`), и MUST закоммитить эти файлы до создания тега — иначе тег указывал бы на коммит без описанных в changelog изменений.

#### Scenario: Публикация без подготовки
- **WHEN** публикация запущена, а секция `[Unreleased]` непуста
- **THEN** скрипт MUST завершиться ошибкой с указанием запустить подготовку, тег и релиз MUST NOT быть созданы

#### Scenario: Нечистое рабочее дерево
- **WHEN** публикация запущена при незакоммиченных изменениях в других файлах проекта
- **THEN** скрипт MUST завершиться ошибкой с указанием закоммичить работу, тег MUST NOT быть создан

### Requirement: Отказ при рассинхроне версии и changelog
Перед созданием тега release-скрипт MUST сверять формат файла `version` и верхнюю секцию `CHANGELOG.md` (учитывая только что проведённый бамп). При расхождении скрипт MUST завершиться ошибкой и MUST NOT создавать тег, релиз или публикацию.

#### Scenario: Changelog отстаёт
- **WHEN** верхняя секция changelog не совпадает с файлом `version`
- **THEN** скрипт завершается ошибкой, тег не создаётся, git-состояние проекта не изменено

#### Scenario: Файл version вне формата
- **WHEN** файл `version` содержит не `MAJOR.MINOR.PATCH` (например, суффикс сборки или пустая строка)
- **THEN** скрипт завершается ошибкой с указанием ожидаемого формата

### Requirement: Релиз не публикуется без changelog-секции новой версии
Git-тег релиза MUST указывать на коммит, в котором `CHANGELOG.md` содержит версионную секцию нового номера. Публикация релиза, чей коммит не содержит соответствующей секции, MUST считаться ошибкой и MUST NOT выполняться.

#### Scenario: Тег на коммите без секции
- **WHEN** попытка создать тег выполнена, а в `CHANGELOG.md` нет секции с номером новой версии
- **THEN** скрипт завершается ошибкой и не публикует релиз
