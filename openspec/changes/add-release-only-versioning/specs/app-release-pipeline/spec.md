## Purpose

Единый release-процесс всех приложений: как из исходников получается опубликованный GitHub-Release с ассетами, доступными для скачивания со витрины, при минимальном участии владельца, и почему публикация релиза является единственным событием, повышающим версию.

## ADDED Requirements

### Requirement: Release-скрипт производит бамп версии
Release-скрипт перед созданием тега MUST классифицировать содержимое секции `## [Unreleased]` файла `CHANGELOG.md`, определить уровень новой версии по наивысшему накопленному уровню, записать новый номер в файл `version` и свернуть секцию `[Unreleased]` в версионную секцию вида `## [X.Y.Z] — дата (УРОВЕНЬ)`. Повышение версии без одновременной публикации релиза MUST NOT выполняться другим механизмом.

#### Scenario: Релиз с накопленными изменениями
- **WHEN** владелец запускает release-скрипт при непустой секции `[Unreleased]`
- **THEN** файл `version` содержит новый номер, секция `[Unreleased]` заменена версионной секцией, тег и релиз созданы под новым номером

#### Scenario: Секция Unreleased пуста
- **WHEN** release-скрипт запущен, а секция `[Unreleased]` отсутствует или пуста
- **THEN** скрипт MUST завершиться с понятной ошибкой «нет накопленных изменений» и MUST NOT создавать тег с прежним или новым номером

### Requirement: Отказ при рассинхроне версии и changelog
Перед созданием release-скрипт MUST сверять формат файла `version` и верхнюю секцию `CHANGELOG.md` (учитывая только что проведённый бамп). При расхождении скрипт MUST завершиться ошибкой и MUST NOT создавать тег, релиз или публикацию.

#### Scenario: Changelog отстаёт
- **WHEN** после бампа верхняя секция changelog не совпадает с файлом `version`
- **THEN** скрипт завершается ошибкой, тег не создаётся, git-состояние проекта не изменено

#### Scenario: Файл version вне формата
- **WHEN** файл `version` содержит не `MAJOR.MINOR.PATCH` (например, суффикс сборки или пустая строка)
- **THEN** скрипт завершается ошибкой с указанием ожидаемого формата

### Requirement: Релиз не публикуется без changelog-секции новой версии
Git-тег релиза MUST указывать на коммит, в котором `CHANGELOG.md` содержит версионную секцию нового номера. Публикация релиза, чей коммит не содержит соответствующей секции, MUST считаться ошибкой и MUST NOT выполняться.

#### Scenario: Тег на коммите без секции
- **WHEN** попытка создать тег выполнена, а в `CHANGELOG.md` нет секции с номером новой версии
- **THEN** скрипт завершается ошибкой и не публикует релиз
