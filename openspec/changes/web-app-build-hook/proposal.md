# Proposal

## Why

Сейчас витрина публикует веб-приложение только из готовой папки `web/` источника.
Для Benchmark это означает рукописную страницу, которая дублирует исходники и
отстаёт от консоли. Сборка статики командой источника прямо на витрине снимает
ограничение: публикуется свежий результат сборки из того же кода, что и само
приложение, а источник не коммитит производные файлы.

## What Changes

- Запись секции `web:` реестра получает опциональное поле `build` — команду
  сборки статики; для записи с `build` папка `web/` не требуется.
- Сборка витрины исполняет команду над свежим клоном источника, передавая ей
  каталог вывода, и публикует результат в `_site/apps/<slug>/`. Провал команды,
  таймаут или отсутствие `index.html` в результате — предупреждение в логе и
  пропуск страницы без падения сборки (как «источник недоступен»).
- Дата web-карточки записи без `data:` берётся из даты последнего коммита
  источника статики: папки `web/`, а для записи с `build` — репозитория-источника.
- Оповещение витрины об обновлении расширяется на исходники сборки: пуш,
  тронувший статику, её исходники или файл данных, запускает внеплановую сборку.
- Пилот — Benchmark: запись получает `build:` и витрина публикует полный read-only
  слепок консоли (из change'а `static-mirror-export` в Benchmark). После приёмки
  рукописная папка `web/` в Benchmark удаляется.
- Сборочное окружение получает зависимости, нужные командам сборки (Flask для
  экспорта Benchmark).

## Capabilities

### New Capabilities

(нет — расширяется существующий механизм публикации веб-приложений)

### Modified Capabilities

- `store-web-apps`: поле `build` в записи реестра; публикация статики из
  результата сборки командой источника; дата карточки для записей со сборкой;
  расширенный триггер оповещения; требование страницы Benchmark приведено
  к полному read-only слепку консоли.

## Impact

- `generate.py` — реестр веб-приложений (поле `build`) и публикация статики
  (исполнение команды над клоном, таймаут, предупреждения, пропуск при провале).
- `registry.yaml` — поле `build` у записи `benchmark`.
- `.github/workflows/build.yml` — установка зависимости Flask в сборочное
  окружение.
- `tests/test_generate.py`, `tests/validate_site.py` — тесты ветки сборки и
  валидация публикуемого вывода.
- `CHANGELOG.md` — пункт о полной консоли на странице `/apps/benchmark/`.
- Внешний: репозиторий Benchmark — после приёмки удаляется папка `web/`
  (реализация change'а `static-mirror-export`).
