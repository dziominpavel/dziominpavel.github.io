# Delta: app-release-pipeline (add-event-driven-store-sync)

## ADDED Requirements

### Requirement: Оповещение витрины о релизе
Release-скрипт MUST после успешной публикации GitHub-Release отправить витрине оповещение о новом релизе (`repository_dispatch`), чтобы сборка витрины запускалась без ожидания расписания. Отправка MUST выполняться в том же запуске скрипта, уже после публикации, и MUST NOT являться критической фазой: при ошибке отправки скрипт MUST вывести предупреждение и MUST завершиться кодом успеха, поскольку релиз уже опубликован; откатывать тег или опубликованный релиз при сбое оповещения MUST NOT. Оповещение MUST отправляться только когда релиз действительно опубликован. Публикация релиза, выпущенная минуя release-скрипт, оповещение MUST NOT отправлять.

#### Scenario: Релиз опубликован, оповещение доставлено
- **WHEN** публикация релиза завершилась успешно и отправка оповещения прошла без ошибки
- **THEN** скрипт печатает результат оповещения и завершается с кодом 0

#### Scenario: Оповещение не удалось отправить
- **WHEN** отправка оповещения завершилась ошибкой (нет сети, истёкший или ограниченный токен, недоступный API)
- **THEN** скрипт печатает предупреждение и завершается с кодом 0; тег и опубликованный релиз остаются без изменений

#### Scenario: Публикация не состоялась
- **WHEN** одна из фаз до публикации завершилась ошибкой и релиз не создан
- **THEN** оповещение витрины MUST NOT отправляться

#### Scenario: Релиз создан минуя release-скрипт
- **WHEN** владелец публикует релиз вручную через веб-интерфейс GitHub
- **THEN** release-скрипт не участвует, оповещение не отправляется, а витрина обновляет данные ближайшей сборкой по расписанию
