# Proposal: fix-release-notes-audience

## Why

Тело GitHub-Release читает пользователь — страница релиза и будущий список
версий на витрине, — но верхний блок секции changelog (он же и есть заметки
релиза) пишется инженерно и без автора: у FogMap в `1.6.0` заметка рассказывает
о механике бампа версии, секции `1.5.2`/`1.5.1` не имеют `###` вообще и уходят
в релиз целиком дампом. Гейт `-Prepare` проверяет только непустоту текста над
`###` — форму, не адресата и не структуру; спека при этом противоречива:
«2–5 строк саммари» (`versioning-policy`) несовместимо со структурированным
блоком, который нужен витрине. Витрина скоро показывает список версий
с краткими изменениями — обе поверхности читают ОДИН body, чинить надо один раз
и одинаково для всех проектов.

## What Changes

- **Формат-контракт верхнего блока секции.** Блок до первой строки `###` =
  жирные метки категорий `**Добавлено**` / `**Исправлено**` (НЕ `###` — иначе
  обрежется извлечением заметок) + буллеты, одна строка = одно изменение.
  Внутри блока запрещены `` ` `` и `###`: запрет кавычек — почти идеальный
  детектор инженерного текста (все три текущие заметки FogMap его не проходят).
  Механика извлечения заметок не меняется; отдельного релиз-описания по-прежнему
  не пишем.
- **Гейт в `release.ps1 -Prepare`.** Эталон — `scripts/release.ps1` этого репо;
  копии в детях править запрещено, доставка — `sync-release.ps1`. Блок MUST
  состоять только из жирных меток и буллетов, содержать ≥1 буллет, строки
  ≤140 символов, без `` ` ``; отказ — до записи файлов, с печатью текста
  и пометкой «это увидят пользователи». Классификатор уровня MUST опознавать
  и жирные метки: иначе секция только с `**Исправлено**` без `###`-секций
  уходит в MINOR, что противоречит требованию `versioning-policy`
  «Классификация уровня при релизе». `$SCRIPT_VERSION` 1.3.0 → 1.4.0
  с рассылкой на все проекты.
- **Единая логика для всех проектов.** Контракт (`docs/versioning.md`) и правило
  авторства (`docs/agents-versioning-block.md` → AGENTS дочерних) — корневые
  эталоны, доставляются одной командой sync; гейт живёт в том же эталонном
  скрипте. Содержательные правки — только там, где равномерность уже сломана:
  FogMap (ремонт секций и тел релизов) и instagram-tracker (в `[Unreleased]`
  нет верхнего блока — следующий `-Prepare` упадёт уже на сегодняшнем гейте).
- **Ремонт FogMap.** Пользовательские блоки в секции `1.6.0` (4 фичи, 5 фиксов),
  в `1.5.2` и `1.5.1` (блок + введение `###`, иначе фолбэк «вся секция = заметки»
  остаётся); закоммит уже сделанного в рабочем дереве удаления дубль-секции
  `## [Unreleased]`. Тела `v1.6.0`/`v1.5.2`/`v1.5.1` выставляются через
  `gh release edit --notes-file`. Остальные 8 тел релизов и секции FogMap
  `1.5.0` и ниже не трогаются.
- **Доки и дистрибуция.** `docs/versioning.md`: формат-контракт + пропуск
  исторических секций без `###`; AGENTS-блок: правило писать верхний блок
  в момент работы, вместе с пунктами под `###`. Оба эталона и блок корневого
  `AGENTS.md` обновляются вместе и уходят sync-ом во все проекты.
- **BREAKING** для релизного процесса: `-Prepare` откажет секциям, чей верхний
  блок не проходит структурную валидацию (свободная проза с кавычками больше
  не проходит). Для скачивающих и витрины ничего не ломается — публикуемое тело
  только станет читабельнее.

Не в скоупе: рендерер витрины «список версий + изменения» (отдельный change
в этом репо), ручные правки копий `release.ps1` у детей, коммиты рассылки
`chore(release): sync release script vN`.

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `openspec/specs/app-release-pipeline/spec.md`: требование «Подготовка релиза
  требует пользовательского саммари» ужесточается с «непустой текст над `###`»
  до структурной валидации блока (только жирные метки и буллеты, ≥1 буллет,
  строки ≤140 символов, без `` ` ``), отказ в `-Prepare` до записи файлов
  с печатью текста.
- `openspec/specs/versioning-policy/spec.md`: требование «Секция changelog
  начинается с пользовательского саммари» заменяет «2–5 строк» формат-контрактом
  блока (жирные метки категорий, одна строка = одно изменение, запрет `` ` ``
  и `###` внутри блока) и уточняет адресата — пользователь проекта.

## Impact

- **Код корня:** `scripts/release.ps1` (гейт, классификатор, `$SCRIPT_VERSION`
  1.4.0), `scripts/sync-release.ps1` (рассылка), `tests/test_release_phases.py`
  (фикстуры и тесты гейта и классификатора).
- **Эталоны-документы:** `docs/versioning.md`, `docs/agents-versioning-block.md`,
  блок `<!-- versioning:begin -->` в корневом `AGENTS.md`, `CHANGELOG.md` корня
  (один пункт о контракте; сам ремонт секций релизов в changelog не записывается).
- **Дети (все проекты `versioning.yaml`):** доставка sync-ом — локальный канал
  (docs, check-version.py, скелет changelog, AGENTS-блок) + `release.ps1`/`.bat`
  для 7 релизных; ручные правки копий запрещены.
- **FogMap:** `CHANGELOG.md` (блоки трёх секций; дубль-секция уже удалена
  в рабочем дереве, нужен коммит по команде владельца), три
  `gh release edit --notes-file` (`gh` установлен и авторизован).
- **instagram-tracker:** `CHANGELOG.md` — верхний блок `[Unreleased]`.
- **Вне скоупа:** рендерер витрины, тела 8 других релизов (уже содержат текст),
  секции FogMap `1.5.0` и ниже, проверка саммари в `check-version.py`
  (возможный отдельный слой контроля).
