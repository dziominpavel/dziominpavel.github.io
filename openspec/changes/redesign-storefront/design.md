## Context

См. proposal.md — Why. Технический контекст, ограничивающий подход:

- Вся разметка страниц инлайнена в `generate.py` (каталог `templates/` содержит только `.gitkeep`), поэтому редизайн — это правки Python-шаблонов + переписывание `static/css/style.css`.
- `tests/validate_site.py` фиксирует обязательные маркеры в каждой HTML-странице: `data-theme="dark"`, подключение `static/js/theme.js`, тексты навигации «Главная» и «О проекте», полноту sitemap, корректность HTML. CSS-классы тестами не зафиксированы — имена классов свободны.
- `static/js/theme.js` сейчас: трёхрежимный цикл `system/dark/light` + `location.reload()` + текстовая кнопка; `data-theme="dark"` жёстко зашит в `<html>`, поэтому светлая тема после перезагрузки мигает тёмной (скрипт ставит тему в конце body).
- Живой сайт уже задеплоен и содержит 7 карточек; любая правка требует цикла `generate.py --out _site` → тесты → push (CI деплоит по `push paths`: `registry.yaml`, `generate.py`, `static/**`).
- Статистика для hero и счётчиков фильтра полностью доступна генератору на этапе сборки (`registry.yaml` + автодетект платформ) — сервер и клиентская логика для неё не нужны.

## Goals / Non-Goals

**Goals:**

- Формальная дизайн-система на CSS custom properties: типографическая шкала, 4px-сетка отступов, радиусы, ступени глубины, motion-токены — и сборка всех страниц только из токенов.
- Тема: ровно два режима (dark/light), default dark, переключение без перезагрузки и без вспышки при загрузке, миграция старого значения `system`.
- Визуальный уровень: sticky-шапка с blur, hero со статистикой, сегментированный фильтр со счётчиками, новая анатомия карточки, выделенный CTA.
- Доступность: `:focus-visible`, `prefers-reduced-motion`, контраст WCAG AA в обеих темах.
- Оба тест-набора (`test_generate.py`, `validate_site.py`) зелёные; нулевые новые внешние зависимости (никаких CDN, фреймворков, библиотек иконок).

**Non-Goals:**

- Изменения контракта данных (`registry.yaml`, `store.yaml`), релиз-процессов приложений, логики сборки данных и автодетекта платформ.
- Новый функционал каталога: поиск, пагинация, страница 404, новые страницы.
- Веб-приложения — отдельное изменение (`add-web-apps`).
- Вынос шаблонов из `generate.py` в `templates/*.html` — возможно позже, не в этом изменении.

## Decisions

### D1. Архитектура темы: `data-theme` + pre-paint inline-скрипт, без reload

`<html data-theme="dark">` остаётся контрактом (валидатор), значения — только `dark`/`light`. В `<head>` **до** `<link rel="stylesheet">` добавляется крошечный inline-скрипт: читает `localStorage['theme']`, допускает только `dark`/`light` (всё прочее, включая устаревшее `system` → `dark`), ставит `document.documentElement.dataset.theme` и обновляет `meta[name=theme-color]`/`color-scheme`. `static/js/theme.js` (подключается как раньше, валидатор требует его в разметке) получает только обработчик кнопки: инверсия `dataset.theme`, запись в `localStorage`, обновление `meta` и `aria-label` — **без `location.reload()`**.

*Альтернативы:* `prefers-color-scheme` — отклонено (требование «без системного режима»); CSS-класс `.dark` на `body` — отклонено (ломает маркер валидатора `data-theme="dark"`); перезагрузка страницы — отклонено (мигание, потеря состояния, медленно).

### D2. Кнопка-иконка солнце/луна: один inline SVG, поворот + кроссфейд

Круглая icon-кнопка 40×40 в шапке, внутри inline SVG из двух слоёв: «солнце» (круг + 8 лучей) и «луна» (полумесяц). Переключение темы анимирует слои: поворот на 90°, кроссфейд, лучи «схлопываются» (scale/stagger), мягкий glow-блик. `aria-label` и `title` меняются синхронно с темой («Переключить на светлую тему»/«…тёмную»). При `prefers-reduced-motion` — мгновенная смена иконки без анимации.

*Альтернативы:* pill-switch с двумя иконками и скользящим кружком — отклонено (визуально как control из настроек, хуже читается на мобильном); текстовая пилюля «Тема: …» — так сейчас, отклонено пользователем; библиотеки иконок/CDN — отклонено (zero-dependency).

### D3. Дизайн-токены — расширение существующих `:root`/`[data-theme]`

Текущие токены (8 шт.) дополняются блоками:

- **Типографика**: `--fs-xs..--fs-3xl` (12/14/15/18/24/34/44), `--lh-*`, `letter-spacing` для заголовоков, `font-variant-numeric: tabular-nums` для версий/размеров/счётчиков.
- **Сетка**: `--sp-1..--sp-16` (множители 4px), радиусы `--r-sm/md/lg/pill` (10/16/24/999).
- **Глубина**: ступени `--bg / --surface / --surface-2 / --elevated` + hairline-границы `--border` (в тёмной `rgba(255,255,255,.06)`, в светлой `rgba(0,0,0,.08)`) вместо «слипающихся» сплошных цветов; две тени (`--shadow-1`, `--shadow-2`).
- **Цвет**: акцент — градиент `#3b82f6 → #6366f1` (синий → индиго: продолжение текущего бренда, но с характером); тинты платформ `--android-tint/--windows-tint` (12% фон чипов/кнопок); CTA — акцентный градиент с белым текстом.
- **Motion**: `--ease: cubic-bezier(.2,.8,.2,1)`, `--dur-fast: 160ms`, `--dur: 240ms`.

Светлая тема переопределяет значения тех же токенов — компоненты не знают о теме.

*Альтернатива:* точечные правки текущих магических чисел — отклонено: корень «непричёсанности» именно в отсутствии системы.

### D4. Разметка — правки только в `generate.py`

- **Шапка**: sticky + `backdrop-filter: blur(12px)` + hairline-бордер, бренд «знак + слово», ghost-ссылки навигации, кнопка темы (D2). Навигационные тексты «Главная», «О проекте» сохраняются дословно (валидатор).
- **Hero**: градиентный заголовок + подзаголовок + полоса статистики, данные («7 приложений · 5 Android · 2 Windows») считаются в Python при генерации.
- **Фильтр**: сегментированная группа в surface-контейнере; счётчики («Все 7», «Android 5», «Windows 2») **бейкаются в HTML генератором**, `filter.js` по-прежнему только переключает видимость карточек — его поведение не меняется.
- **Карточка**: строка иконка/название/чип платформы → версия·размер (tabular-nums) → описание (clamp, 2 строки) → строка счётчиков → действия: primary CTA «Скачать» (первая кнопка платформы) + secondary-кнопки остальных платформ/«Подробнее» + иконка-ссылка на исходники. Все платформенные ассеты остаются видимыми и кликабельными — требование store-catalog «все варианты как кнопки с именами и размерами» сохраняется (стилизация, не удаление).
- **Страница приложения**: галерея скриншотов поднимается выше описания, блок скачивания — в выделенную карточку (на desktop — sticky), требования/подсказки — как сейчас.

*Альтернатива:* шаблонизатор/файловые шаблоны — отклонено как лишний рефакторинг в этом изменении.

### D5. Анимации — только CSS, progressive enhancement

Появление карточек — CSS `animation` со стаггером через `nth-child` (без JS и IntersectionObserver: контент виден сразу, анимация — усиление). Все переходы — `var(--dur)`/`var(--ease)`. Один общий выключатель:

```css
@media (prefers-reduced-motion: reduce) { *, *::before, *::after { animation: none !important; transition: none !important; } }
```

`:focus-visible` — кольцо акцентного цвета со сдвигом на всех интерактивах.

### D6. Контрольный гейт перед каждым push

`python generate.py --out _site` → `python tests/test_generate.py` → `python tests/validate_site.py _site` → ручной проход в браузере: dark/light (включая reload со светлой — нет вспышки), фильтры Все/Android/Windows, обе страницы, mobile + desktop, клавиатурный Tab-проход.

## Risks / Trade-offs

- [Валидатор отклонит страницу из-за потерянного маркера (`data-theme="dark"`, `theme.js`, nav-тексты)] → маркеры перечислены в D4/D6 как обязательные; оба теста гоняются локально до push.
- [Контраст не пройдёт WCAG AA в одной из тем] → пары «текст/подписи на фоне» подбираются под 4.5:1 и проверяются отдельной задачей до финального прогона; токены правятся в одном месте.
- [FOUC: вспышка тёмной темы при сохранённой светлой (или наоборот)] → inline-скрипт строго до подключения стилей; проверяется сценарием «сохранить light → перезагрузить».
- [Весь сайт перерисовывается — высокий шанс визуальной регрессии] → последовательность: сначала токены + базовые компоненты (header, кнопки, карточка), потом сборка страниц; после каждого шага — браузерная проверка в обеих темах.
- [Слом поведения фильтра/темы при переименовании классов] → `filter.js`/`theme.js` обновляются в той же задаче, что и разметка; проверка фильтра — обязательный сценарий гейта (D6).
- [Потребители контракта (7 приложений) не затронуты, но push заденет `static/**` и `generate.py` — CI пересоберёт витрину] → это штатный путь деплоя; rollback = `git revert` + push, CI откатит статику.

## Migration Plan

1. Локально: токены → компоненты (header/карточка/кнопки) → hero+фильтр → страница приложения → тема (D1/D2).
2. После каждой части — `generate.py --out _site` и оба теста; в конце — полный браузерный гейт D6.
3. Push одной веткой/коммитом; CI (`push paths` покрывает `generate.py` и `static/**`) деплоит автоматически; при необходимости — `workflow_dispatch` для немедленного деплоя.
4. Smoke живого сайта: главная, одна страница приложения, смена темы + reload, фильтры.
5. Откат: `git revert` → push → CI публикует прежнюю статику (контракт данных не менялся, откат безопасен).
6. Архивация: изменение MUST быть заархивировано **после** `add-app-store` — дельта `MODIFIED` для `store-catalog` применяется только к существующему основному спеку, который создаётся при архивации `add-app-store` (проверка `openspec validate --strict` сейчас сообщает об этом INFO).
