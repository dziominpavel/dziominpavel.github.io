# Design

## Context

См. `proposal.md` — Why. Текущее состояние, важное для подхода:

- `validate_project()` (`generate.py`, строки 288–296) считает валидным только 3–5 скриншотов; при другом количестве приложение целиком пропускается.
- Пять приложений (GymProgress, VoiceMind, Wishlot, InstagramTracker, YandexMusicDownloader) содержат по три файла `*-placeholder.png` — нарисованные «Скриншоты 1/3» с квадратами вместо кириллицы.
- `gallery_html()` всегда рендерит галерею из `card["screenshots"]`; пустой список даёт пустую строку, и секция исчезает.
- Change `optimize-image-loading` добавляет подготовку производных до рендера HTML и пропускает битые изображения; после него у карточки есть метаданные пригодных превью.
- Витрина пересобирается по cron каждые 30 минут и клонирует репозитории приложений с GitHub; удаление файлов в приложениях влияет только после пуша.

## Goals / Non-Goals

**Goals:**

- Разрешить публикацию приложения с 0–5 скриншотами, не скрывая его из-за их отсутствия.
- Показывать честное, лёгкое и theme-aware состояние вместо фейковых изображений.
- Убрать заглушки из репозиториев приложений и из контракта.
- Не добавлять зависимостей и не менять данные существующих приложений.

**Non-Goals:**

- Генерация raster-превью, обложек карточек и OG-картинок.
- Скриншоты для веб-приложений и автосъёмка скриншотов.
- Изменение формата исходных изображений и пайплайна производных (это `optimize-image-loading`).
- Фильтрация файлов по имени `*-placeholder.*` на стороне стора.

## Decisions

### D1. Fallback — HTML/CSS-блок, а не картинка

Состояние «скриншотов нет» рисуется разметкой: заголовок «Превью», декоративная inline-SVG, текст «Скриншоты появятся позже» и пояснение. Это 0 байт изображений, автоматическая поддержка тёмной и светлой темы, отсутствие проблем со шрифтами и кириллицей (текущие заглушки как раз показывают квадраты) и честное поведение: мы не выдаём заглушку за скриншот.

Альтернативы: raster-макет телефона (10–20 КБ, фиксированная тема, нужен Pillow), три нарисованные заглушки (фейковый контент, ~84 КБ), скрыть секцию (страница выглядит недоделанной).

### D2. Контракт: 0–5, без скрытия за «лишние» файлы

Валидными считаются 0, 1, 2, 3, 4 и 5 изображений. При 0 папка `screenshots/` MAY отсутствовать. Если изображений больше пяти, публикуются первые пять, а в лог идёт предупреждение: скрывать полностью готовое приложение из-за лишнего файла негуманно. Это осознанное смягчение прежнего поведения «вне 3–5 → skip».

Альтернативы: скрывать при >5 (жёстко и неожиданно), не ограничивать количество (галерея и сборка растут без пользы).

### D3. Условие fallback — отсутствие пригодных превью

После `optimize-image-loading` карточка знает, сколько превью удалось подготовить. Fallback включается, когда этот список пуст, а не только когда пуст исходный `screenshots`. Так битые или нечитаемые файлы не приводят к пустой галерее. Если change применяется до C1, используется исходный список; после C1 — метаданные превью.

### D4. Содержимое и оформление блока

```
+------------------------------------------+
|              [image icon]                |
|         Скриншоты появятся позже         |
|  Приложение уже доступно — описание      |
|  и релизы выше.                          |
+------------------------------------------+
```

- Секция сохраняет класс `.gallery` и позицию после «Что нового».
- Внутри — `.preview-empty` с рамкой, центрированием и muted-текстом на CSS-переменных темы.
- Иконка приложения не дублируется: она уже есть в шапке страницы.
- SVG декоративная, `aria-hidden="true"`; текст доступен как обычный текст.
- Никакого `<img>` и сетки `.shots` в этом состоянии.

Альтернативы: повторять иконку и название приложения (дублирование), использовать макет телефона (визуально обещает больше, чем есть).

### D5. Рендер: одна ветка в `gallery_html()`

`gallery_html(card)` проверяет наличие подготовленных превью: если пусто — возвращает секцию «Превью»; иначе — текущую галерею. Отдельный вызов из `APP_TEMPLATE` не нужен, позиция и заголовок остаются в одном месте. CSS добавляет только `.preview-empty` и его текстовые элементы; JS не участвует.

### D6. Миграция: сначала стор, потом удаление заглушек

Порядок важен: старый генератор скрывает приложение с 0 скриншотов. Поэтому:

1. Влить и задеплоить C2 — пять приложений пока ещё с заглушками, но валидация уже принимает 0–5.
2. Убедиться, что все пять приложений на витрине.
3. Удалить по три `*-placeholder.png` в пяти репозиториях и запушить.
4. Дождаться ближайшей сборки: страницы показывают блок «Превью».

Обратный порядок (сначала удалить файлы) на время скрыл бы пять приложений. Фильтр по имени `*-placeholder.*` в сторе не вводим: это скрытая магия, а явное удаление оставляет контракт предсказуемым.

### D7. Документация контракта

Обновляются `README.md` (раздел «Как добавить приложение») и `openspec/config.yaml` (контекст: `screenshots/` 0–5, опционально). Основная спека `store-data-contract` синхронизируется при архивации change; вручную во время реализации её не правим.

### D8. Тесты

- `validate_project`: 0, 1 и 2 скриншота — валидно; 6 — валидно с предупреждением и первыми пятью; отсутствие папки — валидно.
- Рендер: карточка без превью даёт секцию «Превью» без `<img>`; с одним превью — галерею с одним изображением и без fallback.
- Проверка, что заглушки не появляются автоматически и что старый сценарий «мало скриншотов → skip» удалён/переписан.

## Risks / Trade-offs

- **Пять приложений останутся без скриншотов надолго** → это допустимое состояние; блок честно сообщает, что скриншоты появятся позже. Владелец может добавить их в любой момент без правок стора.
- **Галерея из одного изображения выглядит пусто** → сетка `auto-fill` растянет его на одну колонку; лучше, чем фейковые три.
- **Удаление заглушек раньше деплоя C2 скроет приложения** → миграционный порядок D6; при откате C2 сначала восстановить заглушки, иначе старый валидатор снова скроет приложения.
- **`>5` молча теряет лишние изображения** → предупреждение в логе; контракт явно ограничивает пятью.
- **Fallback выглядит как ошибка** → позитивный текст и нейтральное оформление, без красных/алармовых цветов.
- **Пересечение с C1 в `gallery_html()`** → C2 делается после C1; ветка fallback добавляется поверх готовой разметки производных.

## Migration Plan

1. Задеплоить C2 после C1; проверить, что пять приложений с заглушками по-прежнему на витрине.
2. Удалить 15 файлов `*-placeholder.png` в пяти репозиториях, запушить.
3. Дождаться сборки по cron или `repository_dispatch`; проверить блок «Превью» на пяти страницах и отсутствие `<img>` в нём.
4. Откат: revert коммита C2 и восстановление заглушек в пяти репозиториях (в этом порядке, чтобы старый валидатор не скрыл приложения).
